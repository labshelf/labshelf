# Session 1 — Manual checks in Chrome and Firefox

- **Goal:** confirm the PDF-finding flows that need no institutional access in real Chrome and Firefox.
- **Starts from:** a build of the current branch (`pnpm --filter @labshelf/browser build`) loaded into Chrome and into Firefox; typecheck and tests pass.
- **Ends with:** A1–A5 checked in both browsers, or a fix or follow-up session written for each failure; `documents/plans/pdf-finding-checks/` deleted.
  - **A1** When a capture ends in "PDF not found" because of a bot wall, the dialog offers "Open to pass the check". After the user solves it in that tab, the PDF attaches without another click.
  - **A2** With a paper in the library that has no PDF, the user downloads its PDF from any site or opens it in a tab. The toolbar badge appears, the popup offers "Attach to <paper>", and one click attaches it. A PDF of an unrelated paper offers nothing.
  - **A3** For a paper whose only free copy is on arXiv, capture attaches it with `pdfVersion: preprint`, and the "Preprint" badge shows in the browser library, the detail pane and VS Code. "Find Published Version" on it asks before it replaces the file, and warns when highlights exist.
  - **A4** When a capture ends in "PDF not found" with an author address on the page, "Ask the author" opens the mail client with the subject, citation, DOI link and the requester's name and affiliation filled in. The detail pane then says "PDF requested from the author on <date>". With no address, the article page opens and nothing is recorded.
  - **A5** VS Code shows the "PDF requested from the author on <date>" line for the paper from A4.
- **Owns:** none. A fix for a failed check owns the files it touches.

The user runs every check in Chrome and in Firefox; no package touches code unless its check fails. The main thread records each result in `log.md` with `>>`, one line per check and browser.

## 1.1 — Bot wall (A1)

- **Goal:** the "Open to pass the check" dialog attaches the PDF once the user solves the check.
- **Decided:** the bot-wall watch lasts 5 minutes and lives in `storage.session`. The watcher attaches the PDF the tab shows, or up to 3 PDF links of a page whose `citation_title` is the same work. The helper tab often passes PMC's proof-of-work by itself, so a capture may succeed without the dialog; that passes capture but not A1, so try another walled paper (try PMC or Wiley first).
- **Steps:** capture a paper from the toolbar popup whose PDF sits behind a bot check. The dialog must offer "Open to pass the check". Click it, solve the check in the opened tab, and wait without clicking anything else. The toast says the PDF attached.
- **Done when:** A1 in both browsers, or the failing case is logged with the URL and the tab state.

## 1.2 — Attach what was downloaded (A2)

- **Goal:** a downloaded or opened PDF is offered for the matching paper without a PDF.
- **Decided:** the offer re-fetches the bytes from the download's final URL with the user's cookies. One-time signed URLs fail the re-fetch; the popup then offers "Attach PDF…" with the paper preselected. Not checked before: Firefox and a real `downloads.onChanged` event.
- **Steps:** with a library paper that has no PDF, download its PDF from any site; then open another such PDF in a tab. The toolbar badge shows "PDF" and the popup offers "Attach to <paper>"; one click writes `paper.pdf`. Then open a PDF of a paper not in the library: nothing is offered.
- **Done when:** A2 in both browsers.

## 1.3 — Preprint version (A3)

- **Goal:** an arXiv-only paper shows the Preprint badge, and "Find Published Version" asks before replacing.
- **Decided:** `pdfVersion: preprint` is stored per `documents/contracts/library-format.md`.
- **Steps:** capture a paper whose only free copy is on arXiv. Check the "Preprint" chip in the browser library, the detail pane and the VS Code library. Add a highlight, then run "Find Published Version": the dialog asks first and warns about the highlight.
- **Done when:** A3.

## 1.4 and 1.5 — Ask the author (A4, A5)

- **Goal:** "Ask the author" opens a filled mail and records the request; VS Code shows it.
- **Decided:** the `mailto:` hand-off navigates the captured tab; the request is stored as `pdfRequestedAt` per `documents/contracts/library-format.md`.
- **Steps:**
  - set the requester's name and affiliation in the options;
  - capture a paper whose page shows an author e-mail (PLOS, Springer or MDPI) with no PDF reachable. Click "Ask the author": the mail client opens with subject `Request for a copy of "<title>"`, the citation, the DOI link, and the name and affiliation. The detail pane then reads "PDF requested from the author on <date>";
  - repeat with a page without an address: the article page opens and nothing is recorded;
  - after sync, open the first paper in VS Code: the same line shows.
- **Done when:** A4 in both browsers, then A5.

## 1.6 — Close

- **Goal:** every failed check is fixed or has a follow-up; the plan directory is gone.
- **Steps:** fix or open a follow-up for every failed check (a fix gets a failing test first). Then delete `documents/plans/pdf-finding-checks/`.
- **Done when:** the gate passes and the directory is gone.
