# Session 1 — Manual checks in Chrome and Firefox

- **Starts from:** a build of the current branch (`pnpm --filter @labshelf/browser build`) loaded into Chrome and into Firefox; typecheck and tests pass.
- **Ends with:** A1–A5 checked in both browsers, or a fix or follow-up session written for each failure.
- **Commit:** only for fixes and for deleting the plan
- **Research:** none

The user runs every check. The main thread records each result in `../log.md` with `>>`, one line per check and browser.

## S1.1 — Bot wall (A1)

- **Do:** capture a paper from the toolbar popup whose PDF sits behind a bot check (a PMC article, or a Wiley article). The dialog must offer "Open to pass the check". Click it, solve the check in the opened tab, and wait without clicking anything else. The toast says the PDF attached.
- **Context:** the helper tab often passes PMC's proof-of-work by itself, so the capture may succeed without the dialog; that is a pass for capture but not for A1, so try another walled paper. The watcher attaches the PDF the tab shows, or up to 3 PDF links of a page whose `citation_title` is the same work.
- **Done when:** A1 in both browsers, or the failing case is logged with the URL and the tab state.

## S1.2 — Attach what was downloaded (A2)

- **Do:** with a library paper that has no PDF, download its PDF from any site; then open another such PDF in a tab. The toolbar badge shows "PDF" and the popup offers "Attach to <paper>"; one click writes `paper.pdf`. Then open a PDF of a paper not in the library: nothing is offered.
- **Context:** not checked before: Firefox and a real `downloads.onChanged` event. One-time signed URLs fail the re-fetch; the popup then offers "Attach PDF…" with the paper preselected.
- **Done when:** A2 in both browsers.

## S1.3 — Preprint version (A3)

- **Do:** capture a paper whose only free copy is on arXiv. Check the "Preprint" chip in the browser library, the detail pane and the VS Code library. Add a highlight, then run "Find Published Version": the dialog asks first and warns about the highlight.
- **Done when:** A3.

## S1.4 and S1.5 — Ask the author (A4, A5)

- **Do:**
  - Set the requester's name and affiliation in the options.
  - Capture a paper whose page shows an author e-mail (PLOS, Springer or MDPI) with no PDF reachable. Click "Ask the author": the mail client opens with subject `Request for a copy of "<title>"`, the citation, the DOI link, and the name and affiliation. The detail pane then reads "PDF requested from the author on <date>".
  - Repeat with a page without an address: the article page opens and nothing is recorded.
  - After sync, open the first paper in VS Code: the same line shows.
- **Done when:** A4 in both browsers, then A5.

## S1.6 — Close

- **Do:** fix or open a follow-up for every failed check. Add a row to `documents/plans/CALIBRATION.md`. Delete `documents/plans/pdf-finding-checks/`.
- **Done when:** the gate passes and the directory is gone.
