# Rules for every 22a package (read first)
- D1: move the code, re-point every caller in vscode, browser and terminal, delete old files and barrels in the same package. No re-exports left behind. Read the target core module's `index.ts` first and add to the file of the same concept; one concept per file, up to 400 lines (documents/code.md, Modules).
- D2: where the vscode and browser versions behave differently, keep each caller's behaviour through an option or a second named function, unless analysis/reorganization.md §3 names a canonical behaviour. Write a test that pins each difference BEFORE moving. D4: no other behaviour change; protocols, message shapes and on-disk bytes stay identical.
- Core stays runtime-neutral: platform access only through ports the app implements; `node:*` only in the domain's `node/`, DOM only in `dom/`. A core file never imports from an app. Follow current core exports (earlier sessions changed signatures).
- Tests move with the code to packages/core/__tests__/<domain>/; keep every case. An app test is deleted only after the same case runs in core.
- Gate: `pnpm gate core vscode browser` (+ terminal when core exports changed), `pnpm lint:modules`, `pnpm lint:rules`.
- A candidate that no longer exists (earlier session moved it): skip and report. A candidate that is not pure (vscode, DOM or chrome.* call in its body): keep the platform call in the app behind a port and move the rest.
- Read the research file named in the brief (research/22a.md: current paths, callers, effects) instead of fixed line numbers.
