# Brief 2.1 — Canonical isInside with tests

- **Goal:** Write `isInside` in `core/path` and pin its semantics with tests first.
- **Read only:** `documents/plans/reorganization/research/2.md`; `analysis/reorganization.md` §3.4 (lines 500–518); `packages/core/src/path/index.ts`; `packages/core/src/path/pathOps.ts`; `packages/vscode/src/writing/buildRootDocument.ts` (lines 1–40).
- **Decided:**
  - Signature: `isInside(paths: PathOps, folder: string, file: string, options?: { allowEqual?: boolean }): boolean`, in `core/path/pathOps.ts` (or a new `core/path/isInside.ts` if `pathOps.ts` would pass 400 lines), exported from `core/path/index.ts`.
  - Semantics, exactly: `const relative = paths.relative(folder, file); if (relative === "") return options?.allowEqual === true; return relative !== ".." && !relative.startsWith(".." + paths.sep) && !paths.isAbsolute(relative);`
  - The three changes from the current copies, all taken from §3.4: (1) a child named `..notes` is inside (current copies use `startsWith("..")` and call it outside); (2) a relative result that is absolute (a file on another drive on Windows) is outside, which is the `isAbsolute` check that `typstBuilds.ts:36` lacked and the reason its unsaved text could reach a Typst build; (3) `allowEqual` defaults to false. Equal paths: `isInside(paths, "/a", "/a")` is false and `isInside(paths, "/a", "/a", { allowEqual: true })` is true.
  - Per D2, every caller keeps its current equal-path behaviour through `allowEqual`: strict sites (equal is not inside) use the default; inclusive sites (equal is inside) pass `allowEqual: true`. 2.2 to 2.4 apply this; the table is in each brief.
  - The function never throws and does not touch the file system (no `realpath`); symlink handling stays with `bridge/node/pathConfinement.ts`, which is not touched.
