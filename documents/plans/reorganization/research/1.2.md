# Brief 1.2 — LibraryPath and ProjectPath guards, merge the duplicate validators

- **Goal:** One declaration of `LibraryPath` and `ProjectPath` with one guard each in `core/path`, replacing the four validators that mean "a safe relative path".
- **Read only:** `documents/plans/reorganization/research/1.md`; `analysis/typing.md` lines 240–250 and 316–324; `packages/core/src/libraryUi/protocol/messageGuards.ts` (lines 20–40); `packages/core/src/writing/allProjects/protocol/parseAllProjectsMessage.ts` (lines 1–15); `packages/core/src/writing/history/historyEntry.ts` (lines 15–30); `packages/core/src/library/relativePath.ts`; `packages/core/__tests__/library/relativePath.test.ts`.
- **Decided:**
  - Files: `core/path/relativePath.ts` (moved from `library/relativePath.ts`: `checkRelativePath(path: string): string | undefined`, unchanged) and `core/path/brands.ts` (the two types and guards). `core/path/index.ts` exports `checkRelativePath`, `type LibraryPath`, `type ProjectPath`, `isLibraryPath`, `isProjectPath`. Delete `library/relativePath.ts` and its export in `library/index.ts`; move `__tests__/library/relativePath.test.ts` to `__tests__/path/`. Callers keep importing from `@labshelf/core`; re-point only relative imports (research query 4).
  - Brand: `declare const pathBrand: unique symbol; export type LibraryPath = string & { readonly [pathBrand]: "library" }` and the same with `"project"` for `ProjectPath`. No generic `Brand<T>` helper, no other brands (plan D3).
  - `isLibraryPath(value: unknown): value is LibraryPath` keeps today's rule exactly: a string with no backslash whose first `/` segment is `PAPERS_DIR` and whose other segments are not `""`, `"."`, `".."`. Import `PAPERS_DIR` from `../library/layout.js` (the file, not the library barrel).
  - `isProjectPath(value: unknown): value is ProjectPath` is `typeof value === "string" && checkRelativePath(value) === undefined`: no backslash, no drive letter, no leading `/`, no control character (including NUL), no empty, `.` or `..` segment. This is the strictest of the three old guards; it replaces the one in `libraryUi/protocol/messageGuards.ts`, the one in `writing/allProjects/protocol/parseAllProjectsMessage.ts` and the exported one in `writing/history/historyEntry.ts` (remove its export from `writing/history/index.ts`). `isSafeSharePath` (collab), `assertProjectPath` (helper) and `isHelperProjectId` are stricter or different on purpose and stay untouched.
  - D2 differences, all of which only reject more and only for inputs no LabShelf writer produces: the allProjects guard also rejects a backslash, an empty or `.` segment and a control character; the history guard also rejects a backslash and a control character; the libraryUi guard also rejects a drive letter and a control character. The allProjects guard also required non-blank text: keep that by writing `isText(value) && isProjectPath(value)` at its call site. Pin every difference with a test.
  - `libraryUi/protocol/messageGuards.ts` imports both guards from `core/path` and declares neither; remove `isLibraryPath` from `libraryUi/protocol/index.ts` (it is exported from the root through `core/path` now; two `export *` of one name is a compile error).
  - Typing scope in this session: the guards narrow to the brands; no function signature changes to the brands here (later domain sessions adopt them where they touch the code). Make `FieldCheck` entries that call the guards keep returning `boolean`.

- **Test cases (write first):** accepted `papers/a/b`, `papers`, `a/b.tex`; rejected `papers\\x`, `papers/../x`, `/a`, `C:/a`, `C:a`, `a//b`, `./a`, `a/./b`, NUL in a segment, `a\\b`, `""`, and `docs` / `paperz/a` for the library guard.
