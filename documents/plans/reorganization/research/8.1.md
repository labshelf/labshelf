# Brief 8.1 — createListeners and the 4 classes
Read only: research/8.md; reorganization.md §3.6 lines 530–540; the four class files above (listeners field, `onChange`, notify loop).

Decided:
- `packages/core/src/events/createListeners.ts`: `export interface Listeners<T = void> { add(listener: (value: T) => void): () => void; emit(value: T): void; clear(): void }` and `export function createListeners<T = void>(): Listeners<T>`.
- `add` returns an unsubscribe returning `void` (not `Set.delete`'s boolean; the declared type was `() => void` everywhere).
- `emit` iterates the live Set: `for (const listener of set) listener(value)`. No snapshot, no try/catch, no error isolation: a throwing listener propagates and later listeners are skipped, as in the current classes. Do NOT unify isolation (plan §3.6). A listener added during an emit runs in that emit; one removed before its turn is skipped (Set semantics; pin with tests).
- `events/index.ts` re-exports; `packages/core/src/index.ts` gets `export * from "./events/index.js";` so vscode and browser use `@labshelf/core`.
- The four classes keep a one-line `onChange(listener)` returning `this.listeners.add(listener)` (their callers are unaffected); the field becomes `createListeners<...>()`, notify loops become `this.listeners.emit(value)`; `RelaySelector` uses `.clear()` where it clears today.
- Add `packages/core/src/events` to `SHARED_MODULES` in `scripts/lint/modules.mjs` and `- packages/core/src/events: listener registry (createListeners).` to `documents/code.md` "Shared modules".
- Tests first (`__tests__/events/createListeners.test.ts`): add/emit/unsubscribe, double unsubscribe harmless, clear, value passed, add during emit runs, remove before turn skipped, throwing listener propagates and stops the loop, unsubscribe returns `undefined`.
