- **Decided:**
  - Replace a `timer` field plus `clearTimeout(timer); timer = setTimeout(fn, ms)` with `const x = createDebouncer(fn, ms)` and `x.call()`; a place that clears the timer on teardown calls `x.cancel()`. Same delay, same trailing edge, same callback.
  - Sites that accumulate state between calls (a set of pending paths, a counter) keep the accumulation in the caller and debounce only the flush. Sites where the immediate part of the call must run on every call (for example `flash`, `setPrefix`: set a class or prefix at once, clear it later) run the immediate part first and then `x.call()`.
  - A site that does not fit (needs a different delay per call, or leading edge) stays as is and is listed in the log with the reason. Do not change any delay.
  - Tests: where a test file for the site exists keep it green; where timing was untested add one fake-timer test per migrated file that asserts "N rapid calls run the callback once after the delay" (`vi.useFakeTimers`).
