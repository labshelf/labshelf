# Brief 3.1 — core/url with tests, re-point callers

- **Goal:** One URL module for host and origin questions that never throws.
- **Read only:** `documents/plans/reorganization/research/3.md`; `analysis/reorganization.md` §3.5 (lines 520–528) and §4 `core/url` (lines 722–728); `packages/core/src/import/pdfFinder/engine/hostPacer.ts`; `packages/core/src/import/pdfFinder/rules/findRule.ts` (around line 32 and its uses); `packages/browser/src/capture/tab/helperTab.ts` (lines 55–62); `packages/core/src/path/index.ts` and `packages/core/src/index.ts` (to copy the registration pattern).
- **Decided:**
  - Files: `core/url/index.ts` and `core/url/url.ts`; `core/src/index.ts` gains `export * from "./url/index.js";`. Neutral runtime (uses the global `URL`).
  - API:
    - `parseUrl(value: string): URL | undefined` is `try { return new URL(value); } catch { return undefined; }` (the body of `findRule.ts`'s copy).
    - `hostOf(value: string): string` is `parseUrl(value)?.hostname ?? ""`. `URL.hostname` is already lower-case, so the `toLowerCase()` in `signatures.ts` is redundant and that copy merges without a change. `www.` is not stripped and the port is not included: `hostOf("https://www.example.com:8080/x")` is `"www.example.com"`.
    - `originOf(value: string | undefined): string | undefined` is `value ? parseUrl(value)?.origin : undefined` (the body of `helperTab.ts`'s copy; an opaque origin returns the string `"null"` as `URL.origin` does today).
  - Callers: `pageFacts.ts` (2 uses), `signatures.ts` (1), `addFromTabHandler.ts` (1, browser, imports from `@labshelf/core`) delete their `hostOf`; `findRule.ts` deletes its `parseUrl`; `helperTab.ts` deletes its `originOf`.
  - `hostPacer.ts` keeps its own function on purpose (it returns `.host`, which includes the port, accepts a `Request` or `URL`, and returns the input when parsing fails; the port matters for per-host throttling). Rename it `hostKeyOf` so it does not share the exported name `hostOf` (the `shared-name` lint); behaviour unchanged.
  - `helper/node/connection/upgrade.ts` `normaliseOrigin` only strips trailing slashes from a string and does not parse; it is not folded and keeps its name.
  - Register the module: add `"packages/core/src/url"` to `SHARED_MODULES` in `scripts/lint/modules.mjs` (line ~16) and the bullet "`packages/core/src/url`: parse a URL without throwing, host and origin of a URL string." to the Shared modules list of `documents/code.md`.
  - D1: no copy left behind; D4: no behaviour change (the only merge of different code, `signatures.ts`, is behaviourally identical).
