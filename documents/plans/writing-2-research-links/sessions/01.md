## 1.1 — Zotero reader and mapping

- **Goal:** `importZoteroLibrary` reads a Zotero data directory and writes papers, folders and highlights through existing core mutations.
- **Read only:** `packages/core/src/library/mutations/import/newPaper.ts` (`writeNewPaper(ctx, takenIds, targetDir, {citeKey, fields, pdf?, sourceName})`); `.../mutations/context.ts` (`MutationContext`: `fs`, `paths`, `artifacts`, `logger`, `papersRoot`); `packages/core/src/ai/node/openAiDatabase.ts` (lazy `node:sqlite`); `packages/core/src/reader/sidecar/paperDataStore.ts` (`addHighlight(paperId, pageNumber, content, color, position?)`, position normalised 0..1).
- **Decided:**
  - Placement `core/src/import/zotero/node/` with an `index.ts`; any runtime-neutral mapping (item to `PaperRecord` fields, colour map) sits at `core/src/import/zotero/`.
  - `importZoteroLibrary(ctx: MutationContext, deps: { takenIds(): Iterable<string>; highlights: Pick<PaperDataStore, "addHighlight">; pageSizes(pdf: Uint8Array): Promise<Array<{ width: number; height: number }>> }, request: { dataDir: string; targetDir: string }): Promise<ZoteroImportSummary>`, with `ZoteroImportSummary = { imported: number; skipped: number; folders: number }`.
  - Read only a temporary copy of `<dataDir>/zotero.sqlite` (Zotero locks the live file). Read the schema version first (the `version` table, row `schema` = `userdata`); an unsupported version fails naming it and the supported ones.
  - Tables read: `items`, `itemTypes`, `itemData`, `itemDataValues`, `fields`, `creators`, `itemCreators`, `collections` (`parentCollectionID` nests), `collectionItems`, `tags`, `itemTags`, `itemNotes`, `itemAttachments`, `itemAnnotations`. Skip items in `deletedItems`; notes and attachments are children of a parent item.
  - Mapping: collection path becomes folders under `targetDir` (an item in several collections goes to the first, in `collectionID` order); an item in none goes to `targetDir`. Fields: title, authors ("First Last" in creator order), year from `date`, `DOI`, `url`, journal (`publicationTitle`), volume, issue, pages, publisher, abstract to `summary`. Tags to `tags`; child notes (HTML stripped to text, joined with blank lines) to `note`. The first PDF attachment (`linkMode` 0 or 1, path `storage:<name>` resolved under `<dataDir>/storage/<key>/`) is the `pdf`; `sourceName` is its file name.
  - Annotations: only type highlight on the paper's PDF. `position` JSON is `{ pageIndex, rects: [[x1, y1, x2, y2], ...] }` in PDF points with the origin at the bottom-left. Page = `pageIndex + 1`. The box is the union of the rects, normalised with `pageSizes` and flipped to a top-left origin. A missing `position`, an unparseable one or a box outside the page is logged and the highlight skipped. Colour map from Zotero hex: `#ffd400`, `#f19837`, `#aaaaaa` to yellow; `#5fb236` green; `#2ea8e5`, `#a28ae5` blue; `#ff6666` red; `#e56eee` pink; any other yellow. Content is the annotation `text`; an empty text is skipped.
  - Every item that cannot be mapped is logged through `ctx.logger` with its Zotero key and the reason, counted in `skipped`, and skipped.
- **Done when:** tests are written first on a checked-in fixture database (nested collections, tags, a note, a PDF, a highlight, a deleted item, an item with no PDF, an unmappable item, an unsupported schema) and pin the mapping above; core tests and typecheck pass.
- **Do not touch:** the apps, `documents/contracts/`.

## 1.2 — Import commands in VS Code and the terminal

- **Goal:** one command in each app asks for the Zotero data directory, calls `importZoteroLibrary` and reports the result.
- **Read only:** `packages/vscode/src/writing/install/installCommand.ts` and `packages/terminal/src/cli/project/installCommand.ts` (command pattern); `packages/terminal/src/cli/index.ts` and `usage.ts` (registration); `packages/vscode/package.json`.
- **Decided:**
  - Both commands prompt for the Zotero data directory (the folder holding `zotero.sqlite` and `storage/`), import into the library's `papers/` root, and show `Imported <n> papers into <f> folders, skipped <s>`.
  - VS Code: command `labshelf.importZotero` registered in `package.json` `contributes.commands` and the command palette, folder prompt through the open-folder dialog. Terminal: `labshelf import-zotero <dataDir>` listed in `usage.ts`.
  - Apps add only host glue; the importer comes from the core index. Edit `packages/vscode/package.json` and update `documents/apps/README.md` for the two commands.
- **Done when:** both commands run `importZoteroLibrary` over the fixture library from 1.1 and report the counts (A9); vscode and terminal typecheck pass. No test for the glue; report that a real Zotero library was not checked.
- **Do not touch:** `packages/core/src/import/zotero/` beyond its index export, `packages/browser`.
