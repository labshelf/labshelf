## 1.1 — Upgrade sync on a scratch Drive

- **Goal:** run the upgrade sync by hand and record A1–A4.
- **Read only:** nothing required. How to run the extension: `documents/apps/README.md#verifying-changes`. The folder-name contract: `documents/contracts/sync.md#folder-names`. The regression tests that pin this are in `packages/browser/__tests__/sync/` and core's sync engine tests.
- **Decided:**
  - Use a separate browser profile signed in only to the scratch account. Never use a real library or Drive account.
  - Browser sync passes `listTitles` from its paper records and keeps the run record in IndexedDB under `google-drive.last.json`. The engine registers every remote folder under its manifest-first local name and creates folders only for unregistered paths.
- **Steps:**
  - build the extension from a commit before `browserSync` used the coordinator, load it in the test profile and sync two papers to the scratch Drive;
  - load the current build in the same profile, add a file to one old paper and save a new paper, then sync (A1, A2);
  - upload a file on Drive into an old paper's folder and sync again (A3);
  - reload the extension and open the options page (A4).
- **Done when:** A1–A4 hold. Each failure is logged with the Drive folder names and ids; a failure becomes a fix package with a failing test first.
- **Do not touch:** any real library or Drive account; code, unless the check fails.
