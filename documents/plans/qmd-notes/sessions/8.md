## 8.1 — Threads ↔ items and file store

- **Goal:** `.labshelf/comments.qmd` replaces `comments.json` behind the same `loadCommentsDocument`/`editCommentsDocument` API.
- **Read only:** `documents/plans/qmd-notes/research/comments-checklist.md` (comments.json), `documents/contracts/library-format.md:243-265`, `packages/core/src/collab/comments/commentThread.ts`, `packages/core/src/collab/comments/commentsFile.ts`, `packages/core/src/collab/comments/commentsFileStore.ts`, `packages/core/src/collab/comments/commentAnchor.ts:1-30`, `packages/core/src/qmd/index.ts`.
- **Decided:**
  - D8: comments, review comments and suggestions become items in `.labshelf/comments.qmd`; anchor = the existing quote/prefix/suffix anchor.
  - Mapping: each comment is one item. The first comment of a thread carries the thread: `#<thread id>`, `anchor="quote:…"`, `file="<POSIX path>"`, `resolved="true"` only when resolved, and optional `start`/`end` (base64 Yjs relative positions, shared projects only). Replies are items with `thread="<thread id>"` and no anchor. Author and `created` from the comment. Body = comment body (LabShelf Markdown). Thread order = order of first items; reply order = file order. Flat items keep D4's merge per id (two offline replies both survive).
  - Existing ids are kept verbatim as item ids (no `n-` prefix needed for migrated ids; the contract allows any id the parser accepts, new ids use `newItemId`).
  - `COMMENTS_PATH` = `.labshelf/comments.qmd`. An unreadable file is never overwritten (kept rule). Leave `commentsFile.ts` JSON parsing in place for 8.2, which moves it into the migration and deletes the rest.
  - Document the mapping in `qmd-items.md` under a `#comments` anchor and point `library-format.md:243-265` to it.
- **Done when:** tests: threads → file → threads equal; resolved flag; reply order; unknown attributes kept.
- **Do not touch:** `packages/core/src/qmd/items/`, apps.

## 8.4 — Shared `.qmd` docs as Y.XmlFragment

- **Goal:** per Q1 (a), if answered otherwise, stop and report: a shared `.qmd` file's Yjs doc holds its items as ProseMirror fragments bound with y-prosemirror, and the disk mirror serializes them to `.qmd`.
- **Read only:** `documents/plans/qmd-notes/research/spaces-collab.md` (Collaboration), `documents/contracts/collaboration.md:165-215`, `packages/core/src/collab/model/readFileText.ts`, `packages/core/src/collab/mirror/textMirror.ts`, `packages/core/src/collab/model/deriveSharedFileKind.ts`, `packages/core/src/qmd/prosemirror/index.ts`, `packages/core/src/qmd/items/index.ts`.
- **Decided:**
  - Doc shape for a `.qmd` path: `Y.Map "qmd"` with `order: Y.Array<string>` (segment keys: item ids, loose segments `loose-<n>`), `attrs: Y.Map<key, string>` (exact fence line per item), `bodies: Y.Map<key, Y.XmlFragment>` (via `prosemirrorJSONToYXmlFragment`/`yXmlFragmentToProsemirrorJSON` and `bodyToDoc`/`docToBody`). Other text files keep `Y.Text "content"`.
  - Mirror: disk → doc applies an item-level diff (add/remove/reorder ids, replace changed bodies); doc → disk serializes with `serializeItemFile`. Echo guard as for text docs.
  - Code in `packages/core/src/qmd/collab/` (runtime-neutral, `qmdDoc.ts`, `qmdMirror.ts`, `index.ts`); `sharedFileKind` returns a `qmd` kind; `textMirror` dispatches to it.
  - Update `collaboration.md` (text rule l.205 and doc layout l.173) for `.qmd` docs only.
- **Done when:** tests: two Y docs edit different items concurrently and converge; disk round trip is byte-identical on session 1 fixtures; text docs unchanged.
- **Do not touch:** `packages/core/src/collab/binding/`, apps.
