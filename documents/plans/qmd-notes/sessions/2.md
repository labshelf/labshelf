## 2.1 — Three-way block merge

- **Goal:** `mergeItemFiles(base, local, other): {merged: string, conflicts: number}` as pure runtime-neutral code.
- **Read only:** `documents/contracts/qmd-items.md`, `packages/core/src/qmd/index.ts`, `packages/core/src/qmd/items/parseItemFile.ts`, `packages/core/src/writing/merge/textMerge.ts:1-60` (`createTextMerge`, diff3 with markers), `packages/core/src/writing/merge/index.ts`.
- **Decided:**
  - D4: three-way against the existing per-device base, keyed by item id: union of new items; one-sided edits kept; deletes honoured; edit beats delete; both-sided edits merged as text inside the item with `createTextMerge` (markers only inside that item's body).
  - Order: items keep base order; items added on one side keep their position after their preceding neighbour on that side; when both sides add items at the same spot, order by id (ULID is time-sortable).
  - Loose text segments merge as text with `createTextMerge` on the concatenated loose text between the same item neighbours.
  - Output blocks are part of the item body; an output with a different `source` on each side keeps the one whose `ran` is later.
  - Files: `packages/core/src/qmd/merge/mergeItemFiles.ts`, `itemOrder.ts`, `index.ts`. Take the text merge as an injected function so the root stays runtime-neutral.
  - Without a base: two-way union by id, both-sided differing bodies get text markers inside the item.
- **Done when:** tests cover every D4 rule and A2 (two appends → both present, no markers; delete vs untouched → deleted; delete vs edit → edited).
- **Do not touch:** `packages/core/src/writing/`, `packages/core/src/library/`.
