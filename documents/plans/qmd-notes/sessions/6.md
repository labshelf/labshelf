## 6.1 — Paper notes store

- **Goal:** `PaperNotesStore` with `read(paperId): ItemFile`, `addItem(paperId, {anchor, body, author})`, `editItem(paperId, id, body)`, `setAnchor(paperId, id, anchor)` (text boxes move in session 7), `removeItem(paperId, id)`, serial per paper.
- **Read only:** `documents/plans/qmd-notes/research/reader.md` (Annotations and sidecar), `packages/core/src/reader/sidecar/paperSidecarStore.ts:20-45,79-142` (queue, injected ids, write pattern), `packages/core/src/library/layout.ts:1-70` (paths :12, :48-63), `packages/core/src/qmd/index.ts`, `packages/core/src/qmd/items/itemEdit.ts`.
- **Decided:** D6: paper notes live in `.research/papers/<id>/notes.qmd` (browser: IndexedDB `appdata/<id>/notes.qmd` beside `data.json`). Add `paperNotesPath(id)` next to the `data.json` path in `library/layout.ts`. File IO goes through the same injected file access the sidecar store uses; if that port is `data.json`-specific, declare `IPaperNotesFiles {read(paperId): Promise<string | null>; write(paperId, text): Promise<void>}` in `qmd/paperNotes/`. A missing file reads as empty. Each write re-reads, applies the edit, writes atomically. Unparseable content is impossible (parser keeps loose text), so nothing is ever overwritten blind. Log every write failure through `ILogger`.
- **Done when:** tests: add to missing file, edit, remove, concurrent adds on one paper keep both.

## 6.2 — Migration

- **Goal:** `migratePaperNotes(paperId)` moves the record `note` and `type: "note"` annotations into `notes.qmd`.
- **Read only:** `packages/core/src/model/paperRecord.ts:1-40`, `packages/core/src/library/paperMetadata.ts:40-70`, `packages/core/src/library/mutations/paperRecordWrite.ts:1-40`, `packages/core/src/model/annotation.ts`, `packages/core/src/reader/sidecar/paperSidecarStore.ts:97-142`, `packages/core/src/qmd/paperNotes/index.ts`.
- **Decided:**
  - File `packages/core/src/qmd/migrations/paperNoteMigration.ts`; header line 2: `// Delete when library-format.md stops listing the \`note\` key and \`type: "note"\` annotations as readable (a format version bump by a later plan).`
  - Order for data safety: append items to `notes.qmd`, read the file back and check the items are there, only then remove the `note` key from `metadata.yaml` and the note annotations from `data.json`. Any failure leaves the sources untouched and logs.
  - Record `note` → one item, anchor none, `created` = record's updated time if any else now, `author` empty, attribute `migrated="note"`. Each note annotation → one item, anchor none, `created` = its `createdAt`, body = `content`, attribute `migrated="annotation:<annotation id>"`. A rerun skips items whose `migrated` value already exists (idempotent after a crash between steps).
  - Body text is written as is (plain text is valid LabShelf Markdown); no rewriting.
  - Runs when a paper is loaded for read or write by the library (one call site per app's composition, wired in 6.5/6.6), never in a hot loop; logs one line per migrated paper.
- **Done when:** tests: note only, annotations only, both, rerun after simulated crash, empty note skipped, read-back failure leaves sources intact.
- **Do not touch:** apps.
