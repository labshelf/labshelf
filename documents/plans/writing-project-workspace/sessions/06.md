## S6.1 — Arc mark in core

- **Shape (D22):** 12px, a faint full track (~22% opacity) plus a round-capped arc, stroke ~1.4, no fill. Progress is the arc length: 0 (track only), half, full. A colour code is a full arc in its tone. Tones: desaturated err / warn / ok / accent tokens.
- **Mapping:** Unread = 0 accent; Reading = half accent; Done = full ok; open item = 0; done item = full ok; broken/error = full err; stale/warning = full warn. Project row: err if broken or the last build failed, warn if anything is open, else ok.
- **Do:** a core builder `arcMark(tone, progress) → SVG string` in `core/src/ui/icons/`, plus a DOM component with an `aria-label`. On hover, the label slides in left of the mark, the mark never moves, and `prefers-reduced-motion` shows it without motion. Add the CSS to the core design system.
- **Do:** native trees cannot read CSS variables (R7). Core exports the resolved light/dark values of the four tones. If tokens exist only in `tokens.css`, add the TS map plus a test asserting it equals `tokens.css`. vscode writes `marks/<tone>-<progress>-<theme>.svg` to `globalStorageUri` once at activation and returns `{light, dark}` for `TreeItem.iconPath`, as `vscode/src/ui/tabIcon.ts` does. The label goes in the TreeItem tooltip.
- **Do:** replace the reading-list and figure-status `ThemeIcon`s with Arc marks and delete what that leaves unused. Pills stay ([core-no-pills](../../core-no-pills/plan.md)).
- **Touch:** `core/src/ui/icons/`, `core/src/ui/dom/`, `vscode/src/ui/`, `vscode/src/writing/{figures,readingList}/`. **Do not touch:** library-ui pills.
- **Test first:** SVG per (tone, progress) snapshot; the token map equals `tokens.css`; icon files written once.
- **Done when:** tests pass; the marks render in a headless webview check.

- **Do:** a section locator: for a (file, line), the nearest heading above it from the LaTeX section scanner or the Typst scan (S4.2); none → the file's own node; included files → named by file (D14).
