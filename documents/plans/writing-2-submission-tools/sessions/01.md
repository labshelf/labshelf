## 1.1 — Review splitting and rebuttal store

- **Goal:** `splitReviews` and a store for `.labshelf/rebuttal/<round>.json` in `core/src/writing/rebuttal/` (runtime-neutral, with an `index.ts`).
- **Read only:** `packages/core/src/writing/versions/versionInfo.ts` (a validated-on-read synced file; `parseJsonObject` from `../project/index.js`); the `.labshelf/versions/` section of `documents/contracts/library-format.md`; `packages/core/src/ports/fileSystem.ts` (`IFileSystem`: `ensureDir`, `writeText`, `readText`, `exists`).
- **Decided:**
  - `splitReviews(text: string): ReviewPoint[]` splits pasted text per reviewer (headings such as "Reviewer 2" or "Review #2"; no heading means one reviewer) and per numbered (`1.`, `1)`, `(1)`) or bulleted (`-`, `*`) point; continuation lines join their point; text before the first point of a reviewer is kept as point 0 only when non-empty. The user edits the result, so nothing is dropped silently.
  - `ReviewPoint = { reviewer: string; number: number; text: string; status: "open" | "addressed" | "wontfix"; reply: string; threadIds: string[] }`. `threadIds` are ids of the writing-sync comment threads; the store never copies comment text. A new point has status `open`, an empty reply and no threads.
  - File `.labshelf/rebuttal/<round>.json`, `<round>` a lowercase ASCII slug of the round name like a version slug: `{ "round": "Round 1", "created": "<ISO 8601>", "points": ReviewPoint[] }`. The folder syncs with the project. Read validates because the file arrives from other machines: an invalid point is dropped and logged through the injected `ILogger`; a file that is not a JSON object with a non-empty `round` and a valid `created` reads as missing. Write is two-space JSON with a final newline.
  - API: `readRebuttal(fs, folder, round)`, `writeRebuttal(fs, folder, rebuttal)`, `listRebuttals(fs, folder)`; paths are project-relative to `folder`.
  - Add a `.labshelf/rebuttal/` section to `library-format.md` in the same change.
- **Done when:** tests written first on real review texts (several reviewers, numbered and bulleted, with and without headings, wrapped lines) pin the points; store round-trips and invalid-file cases pass; core tests and typecheck pass; `architecture-reviewer` reports the contract and the code agree.
- **Do not touch:** `core/src/writing/versions/`, `core/src/writing/compare/`.

## 1.2 — Panel and letter export

- **Goal:** a "Rebuttal" panel and "Export response" in VS Code, with the letter built in core.
- **Read only:** `packages/vscode/src/writing/versions/` (`ComparePanels.ts`, `registerMarkVersionCommand.ts`: panel and command pattern); `packages/core/src/writing/versions/index.ts` (`VersionInfo { slug, name, created }`); `packages/core/src/writing/compare/index.ts` (`diffPages(before, after, pixelsPerPoint): PdfChanges { before, after: PageArea[] }`).
- **Decided:**
  - Core `buildResponseLetter(points: readonly ReviewPoint[], changes: readonly { page: number; text: string }[], format: "markdown" | "latex"): string` in `core/src/writing/rebuttal/`. Per point, in reviewer and number order: the quoted point, the reply, and the changed passages tied to it; LaTeX escapes its special characters. Test only this function, on a fixed set of points.
  - Panel in `packages/vscode/src/writing/rebuttal/`: paste reviews, edit the numbered points, set each status, link a point to comment threads. Changed passages come from comparing the version marked "submitted" (or the one the user picks) with the current build. Uses core components and `--ls-*` tokens; UI text is folder, paper, status. No test for the panel.
- **Done when:** A5 on a fixture project; the letter test and vscode and core typecheck pass.
- **Do not touch:** the store format from 1.1 beyond what A5 needs, `core/src/reader/`.
