  - Store the points in `.labshelf/rebuttal/<round>.json`: reviewer, number, text, status (open, addressed, won't fix) and the linked comment threads.
  - Add a `.labshelf/rebuttal/` section to `documents/contracts/library-format.md` in the same change as the store (the on-disk format is a contract; it is synced with the project like `.labshelf/versions/`).

## S11 — Panel, links to comments, export

- **Do:**
  - A "Rebuttal" panel in VS Code (`packages/vscode/src/writing/`): paste reviews, edit the numbered points, set each point's status, link a point to the comment threads of its source ranges.
  - "Export response" writes a Markdown or LaTeX letter quoting each point, the reply and the changed passages taken from the latest version comparison (`core/src/writing/compare/`, versions in `core/src/writing/versions/`).
  - The panel uses core components and `--ls-*` tokens; UI text uses the product vocabulary.
- **Touch:** `packages/vscode/src/writing/` (rebuttal folder and command registration), `packages/core/src/writing/rebuttal/` (export of the letter, which other apps can run). **Do not touch:** the store format from S10 beyond what A5 needs, `core/src/reader/`.
- **Context:** the changed passages come from the comparison between the version marked "submitted" (or the one the user picks) and the current build.
- **Test first:** n/a for the panel glue; core tests pin the letter for a fixed set of points.
- **Done when:** A5: pasted reviews become numbered points; marking all addressed and exporting writes a letter with quotes, replies and changed passages.
