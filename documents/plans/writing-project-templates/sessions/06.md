## 6.2 — Sync engine

- **Goal:** the sync engine mirrors `<library>/templates/` to `LabShelf Templates`, and Drive-only templates appear in the gallery as Mine.
- **Read only:** `packages/core/src/sync/drive/googleDriveProvider.ts` lines 30–35 (`topLevelName`); `packages/core/src/sync/engine/syncTypes.ts` lines 15–30, 60–90; `packages/core/src/sync/engine/pipeline/syncEngine.ts` lines 15–90 (`FolderNamespace`, `NAMESPACES`, `syncNamespace`); `packages/core/src/sync/provider/` (`RemoteNamespace`); `packages/vscode/src/sync/adapter/syncController.ts`; `packages/core/src/writing/templates/node/mineSource.ts` (reads `<library>/templates/`).
- **Decided:** `RemoteNamespace` gains `"templates"`; `topLevelName` maps it to `LabShelf Templates`; the engine treats it as a folder namespace (root `<library>/templates/`), run with the same root-change rule as the others. INVARIANT: a stored manifest without a `templates` key loads as an empty namespace, so existing libraries do not re-sync from scratch. The project scanner never lists `templates/`; `projects/` and `templates/` stay separate folders. Register the namespace in the VS Code sync composition. Do not change the conflict rules.
- **Tests first:** a template folder round-trips through the fake Drive provider (upload on one library, download into another); a manifest without `templates` loads; a changed Drive root for `templates` runs a first sync that deletes nothing locally; the projects scan ignores `templates/`.
- **Done when:** the tests pass, and `pnpm --filter @labshelf/core typecheck test` and `pnpm --filter @labshelf/vscode typecheck test` pass. `architecture-reviewer` runs on the diff against the three contracts (Drive writes).
