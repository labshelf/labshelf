## 1.1 — Scholarly-host test

- **Goal:** one pure core function says whether a URL's host is scholarly.
- **Read only:** `packages/core/src/import/pdfFinding/rules/` (the rule table and its index).
- **Decided:** `isScholarlyHost(url)` sits beside the rule table and reads its hosts, so a new rule widens it on its own. It adds PubMed, PMC, Europe PMC, arXiv, bioRxiv, medRxiv, SciELO, Semantic Scholar, OpenAlex and doi.org. It is runtime-neutral and exported from core's index.
- **Done when:** tests written first over publisher, repository and non-scholarly hosts (`scirp.org/reference`, `wikipedia.org`) pass; `pnpm --filter @labshelf/core typecheck` and `test` pass.
- **Do not touch:** the rules themselves; `packages/browser`.

## 1.2 — Shared result button

- **Goal:** move the Scholar button into a shared module so Google can reuse it, with no behaviour change.
- **Read only:** `packages/browser/src/content/scholar.ts` (199 lines), `scholarParse.ts`, `packages/browser/src/capture/scholarCapture.ts`, `packages/browser/src/platform/runtimeMessages.ts`, the background capture handler.
- **Decided:**
  - Split button, states, folder menu and the "no PDF" ask move to `content/resultButton/`.
  - `scholar.ts` and `scholarParse.ts` move to `content/scholar/`.
  - `ScholarHit` becomes `SearchHit`; `scholarCapture.ts` becomes `searchHitCapture.ts`; every importer and message name follows.
  - The capture resolves both kinds of hit: id in the links, then the landing page, then a title search checked against the printed year and authors.
  - The button sits on the result's URL line, in a shadow root. The Google script cannot copy from `scholar.ts` (AGENTS.md §1).
- **Done when:** A4; the Scholar tests pass with only renames; browser typecheck passes.
- **Do not touch:** core.

## 1.3 — Google adapter

- **Goal:** parse organic Google results into `SearchHit`s and mount the shared button on scholarly ones.
- **Read only:** `packages/browser/src/content/resultButton/` public API, `content/scholar/` as the adapter pattern, `packages/core` exports `extractDoi`, `arxivIdFromUrl`, `pmidFromUrl`, `isScholarlyHost`; `packages/browser/manifest.chrome.json`, `manifest.firefox.json`.
- **Decided:**
  - Adapter in `packages/browser/src/content/google/`. Organic results sit in `div#search` result blocks; key the parser on the result link and its `h3`.
  - A result gets the button when `isScholarlyHost` holds for its link, or its link or snippet carries a DOI, arXiv id or PMID. Authors and year come from the "author · year" line ("de TF Smith · 1981").
  - Only organic results on the "All" tab: no ads, AI overview, "People also ask", news, images or video. Watch for results Google adds after load.
  - Add `https://www.google.*/search*` to the Scholar content script entry's `include_globs` in both manifests.
  - Save 3 result pages as fixtures: a DOI search, a title search, a `hl=pt-BR` page. A non-article page on a publisher host ends in the existing "not a paper" message.
- **Done when:** tests written first over the 3 fixtures and the ad and AI-overview exclusions pass (A5); A3; `pnpm -r typecheck` and `pnpm -r test` pass.
- **Do not touch:** `content/resultButton/` beyond its public API; core.
