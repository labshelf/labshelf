## 4.1 — OCT

- **Goal:** a room created in VS Code can be joined from the page and the other way round.
- **Decided:** live sessions use Open Collaboration Tools, which ships a Monaco integration (`open-collaboration-monaco`); use that or the OCT web extension, whichever the spike recorded as working (the spike writes it here: <OCT path>) (D6). Reuse the OCT sign-in flow; the page adds no second account. Code lives only in `packages/browser/src/editor/collab/`. The comment storage the VS Code extension already uses runs unchanged in the web build, so a comment is a file change that the page's file system writes and the user's sync tool carries (A4).
- **Read only:** `packages/browser/src/editor/` index and the file system provider from session 3; the OCT packages' README after install.
- **Done when:** a room opens from the page and OCT's Monaco binding attaches to the page's editor; `pnpm --filter @labshelf/browser typecheck && pnpm --filter @labshelf/browser build`. No unit test: the wiring is third-party glue.
- **Do not touch:** `packages/vscode/`, `core` contracts, the rest of `packages/browser/src/editor/`.

## 4.2 — Real session

- **Goal:** A4 and A5 observed with a real session.
- **Do:** start a live session in VS Code and join it from the page; confirm the host's cursor shows. Add a comment in the browser and see it in VS Code, then the reverse.
- **Constraints:** VS Code runs only from a `@vscode/test-electron` copy with its own user-data-dir; ask the user before launching it. Never kill VS Code by name; stop only the launched PID.
- **Done when:** A4 and A5 observed, reported with what was not checked.
