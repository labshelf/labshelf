# Session 3 — the editor page

- **Goal:** an extension page in the browser hosts the editor over the project's IndexedDB files, with live Typst preview and a read-only LaTeX path.
- **Starts from:** session 2 committed (web build of the extension exists).
- **Ends with:**
  - **A1** "Edit" on a project in the browser's Writing tab opens the editor page with its files, without a second sign-in.
  - **A2** In a Typst project, citation completion from the library, Tinymist diagnostics and the live preview work as in VS Code.
  - **A3** Saving writes to IndexedDB and syncs to Drive with the three-way merge; the change reaches VS Code on the next sync.
  - **A6** A LaTeX project opens for editing and shows its last PDF with "Compile on desktop".
  - **A7** Cold start of the editor page stays under 3 s on a mid-range laptop.
- **Owns:** `packages/browser/src/editor/` (not `collab/`), `packages/browser/__tests__/editor/`, the browser manifest and build script.

## Shared decisions

- The editor is `monaco-vscode-api` hosting the LabShelf extension's web build (session 2) and Tinymist's web build, both bundled and pinned in the package (D1, D3). Versions are exact, not ranges.
- The workbench shows only the editor, the LabShelf views and the panels a writer needs; no activity bar of a code IDE (D2).
- The page reuses the extension's Drive sign-in and the projects in IndexedDB; nothing is configured twice (D4).
- LaTeX compiles only on desktop (D5). Everything lives in `packages/browser/src/editor/`; no code is copied from `packages/vscode/`, and `core` contracts do not change.

## 3.1 — Editor page and layout

- **Goal:** a page in the extension boots `monaco-vscode-api` with service overrides and the trimmed layout, and loads the two web extensions bundled in the package.
- **Read only:** the browser manifest and build script; the Writing tab that offers "Edit" (`grep -rn "Writing" packages/browser/src`); the web build output of session 2.
- **Done when:** the page opens a project's files; `pnpm --filter @labshelf/browser typecheck && pnpm --filter @labshelf/browser build`. The page's CSP allows `'wasm-unsafe-eval'` as the reader does (`documents/contracts/reader-host.md`) and nothing else beyond what the bundled web extensions need.
- **Do not touch:** `packages/vscode/`, `core`.

## 3.2 — File system

- **Goal:** a `FileSystemProvider` for the `labshelf-project:` scheme over the IndexedDB project store; a write triggers the browser's existing sync debounce.
- **Read only:** the IndexedDB project store and the sync debounce entry in `packages/browser/src` (find with `grep -rn "IndexedDB\|indexedDB" packages/browser/src`); the extension's Drive sign-in reuse (D4).
- **Decided:** the provider implements read, write, delete, rename, create-directory and directory listing against the project store; it does not change sync internals.
- **Done when:** tests in `packages/browser/__tests__/editor/`, written first, pin read, write and directory listing against the project store, and that a write reaches the sync debounce without losing a concurrent edit (A3, data loss); typecheck and test for `@labshelf/browser`.
- **Do not touch:** sync internals in `core`.

## 3.3 — Preview and LaTeX path

- **Goal:** Typst compiles live through `typst.ts` in the preview; a LaTeX project edits and shows its last synced PDF with "Compile on desktop".
- **Done when:** A2 and A6 hold in the page; typecheck and test for `@labshelf/browser`.
- **Do not touch:** `packages/vscode/`.

## 3.4 — Real run

- **Goal:** the page is run for real and cold start measured.
- **Do:** run the built extension in a headless Chromium (Playwright headless shell; Chrome.app fails headless), open a Typst and a LaTeX project from the Writing tab, and measure the time from page open to an editable file on the machine.
- **Done when:** A1, A2, A3, A6 observed and A7 under 3 s, reported with the numbers and what was not checked.
