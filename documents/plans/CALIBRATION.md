# Estimate calibration

When a plan is done, compare its estimated size with what it really took. Brainstorm and orchestrate read this file before sizing new work, and correct for the bias it shows.

Keep the 20 most recent rows; delete older ones. Update the bias line whenever a row is added.

**Bias so far:** seven plans, and all held their session count. Targets that depend on account-level settings (connectors, skills) or on the user's own access (an institution, a Drive) can miss even when every project step lands; confirm the access and measure them in session 1. Findings carried over from an earlier plan can rest on a wrong premise, so a diagnose step goes before any fix sized on that premise. Line-count estimates for reductions run about 25 % high, because checks turn some findings into "keep" and moves into core add barrels. The scope inside sessions is under-estimated: closing steps absorb baseline clean-up, and multi-agent steps cost several times their estimate in subagent tokens (a council runs about 200k, not 30k). Size work by sessions, and budget agent fan-out separately.
