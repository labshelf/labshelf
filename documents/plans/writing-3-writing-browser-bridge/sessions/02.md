## S4 — Side panel

- **Do:** a side panel (`chrome.sidePanel`; the sidebar in Firefox) that searches the library with core search (D2).

- **Done when:** the panel lists papers.

## S5 — Editor adapters

- **Do:** per site, detect the focused editor element; insert with `document.execCommand('insertText')` or an `InputEvent`; verify the text landed, else copy `\cite{key}` (or `@key`) to the clipboard and tell the user (D3). The side panel talks to the tab's content script through the background.
- **Touch:** `packages/browser/src/content/editors/` (one adapter per site: Overleaf, typst.app), side panel, background. **Do not touch:** editor internals; no scraping of the editor DOM.
- **Context:** content scripts run only on `overleaf.com` and `typst.app`, requested as optional host permissions. Overleaf may reject synthetic input (R1): the clipboard fallback is part of the design. If `insertText` is blocked, the plan grows to GG.
- **Done when:** A2 (Overleaf inserts `\cite{key}`, typst.app inserts `@key`) and A3 (with `insertText` blocked, the panel copies the citation and says so), both on the live sites.
