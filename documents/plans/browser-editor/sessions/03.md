- **Goal:** an extension page in the browser hosts the editor over the project's files, read through the native bridge, with live Typst preview and LaTeX compiled through LabShelf Helper.
- **Starts from:** session 2 committed (web build of the extension exists); `browser-writing-companion` sessions 1a and 2a committed (project store, Writing tab); `browser-latex-helper` session 4 committed (`ILatexHelper`, setup card).
- **Ends with:**
  - **A1** "Edit" on a project in the browser's Writing tab opens the editor page with its files, without a second sign-in.
  - **A2** In a Typst project, citation completion from the library, Tinymist diagnostics and the live preview work as in VS Code.
  - **A3** Saving writes the file into the project folder through the native bridge; the user's sync tool carries it, and VS Code on the same device sees it at once.
  - **A6** A LaTeX project compiles through the helper; with no helper, the setup card shows and the last PDF stays visible.
  - **A7** Cold start of the editor page stays under 3 s on a mid-range laptop.
- **Owns:** `packages/browser/src/editor/` (not `collab/`), `packages/browser/__tests__/editor/`, the browser manifest and build script.

## Shared decisions

- The editor is `monaco-vscode-api` hosting the LabShelf extension's web build (session 2) and Tinymist's web build, both bundled and pinned in the package (D1, D3). Versions are exact, not ranges.
- The workbench shows only the editor, the LabShelf views and the panels a writer needs; no activity bar of a code IDE (D2).
- The page reuses the extension's project store over the native bridge of plan `folder-sync`; nothing is configured twice (D4).
- LaTeX compiles through `ILatexHelper`; without the helper, the page mounts the setup card from `packages/browser/src/helper/` (D5). Everything lives in `packages/browser/src/editor/`; no code is copied from `packages/vscode/`, and `core` contracts do not change.

## 3.1 — Editor page and layout

- **Goal:** a page in the extension boots `monaco-vscode-api` with service overrides and the trimmed layout, and loads the two web extensions bundled in the package.
- **Read only:** the browser manifest and build script; the Writing tab that offers "Edit" (`grep -rn "Writing" packages/browser/src`); the web build output of session 2.
- **Done when:** the page opens a project's files; `pnpm --filter @labshelf/browser typecheck && pnpm --filter @labshelf/browser build`. The page's CSP allows `'wasm-unsafe-eval'` as the reader does (`documents/contracts/reader-host.md`) and nothing else beyond what the bundled web extensions need.
- **Do not touch:** `packages/vscode/`, `core`.

## 3.2 — File system

- **Goal:** a `FileSystemProvider` for the `labshelf-project:` scheme over the browser project store (`packages/browser/src/storage/projects/`, which reads and writes project folders through the native bridge).
- **Read only:** `packages/browser/src/storage/projects/index.ts` (`listBrowserProjects`, `readProjectFile`, `writeProjectFile`).
- **Decided:** the provider implements read, write, delete, rename, create-directory and directory listing against the project store; it does not change the store or the bridge.
- **Done when:** tests in `packages/browser/__tests__/editor/`, written first, pin read, write and directory listing against the project store, and that a write reaches the store without losing a concurrent edit, and a failed write is reported and keeps the editor's text (A3, data loss); typecheck and test for `@labshelf/browser`.
- **Do not touch:** the project store and the native bridge.

## 3.3 — Preview and LaTeX path

- **Goal:** Typst compiles live through `typst.ts` in the preview; a LaTeX project compiles through `ILatexHelper` and shows the built PDF, and with no helper the page mounts the helper setup card and keeps the last synced PDF visible.
- **Read only:** `packages/browser/src/helper/` index (`ILatexHelper`, the setup card), from plan `browser-latex-helper` session 4.
- **Done when:** A2 and A6 hold in the page; tests pin that a LaTeX compile goes through `ILatexHelper` and that a missing helper mounts the card; typecheck and test for `@labshelf/browser`.
- **Do not touch:** `packages/vscode/`.

## 3.4 — Real run

- **Goal:** the page is run for real and cold start measured.
- **Do:** run the built extension in a headless Chromium (Playwright headless shell; Chrome.app fails headless), open a Typst and a LaTeX project from the Writing tab, compile the LaTeX project through the installed helper and observe the PDF, and measure the time from page open to an editable file on the machine.
- **Done when:** A1, A2, A3, A6 observed and A7 under 3 s, reported with the numbers and what was not checked.
