# VS Code extension

Read when you build, change or verify the VS Code extension.

The full LabShelf workspace inside VS Code:

- one sidebar webview in the activity bar with collapsible Library (the shared core folder tree) and Projects sections, and a Settings gear in its title bar;
- the paper list and detail pane in an editor tab;
- the PDF reader;
- import with OCR;
- similar-paper indexing;
- LaTeX and Typst projects in the sidebar's Projects section: Explore templates, All projects and My projects (a folder tree, where a row shows its TEX or TYP label and, once counted, the number of open TODOs, broken references, stale figures and checklist items; a missing folder reads "missing"). The row tooltip shows its main file and engine, the last build, reading progress and stale figures. Opening a project replaces the section with that project's Files, Outline and Checklist, plus the Figures view; Explore templates, All projects and My projects return when the project closes. The All projects editor tab lists every project, including archived and trashed ones, and holds the rename, archive, duplicate, trash, restore and delete-forever actions; a project row expands, like a paper in the Library, into its files, and clicking a file opens the project at that file. A row shows the project title with a venue chip (the target venue and the time left to its deadline), the engine, the number of cites, a build dot and the last modified time; the expanded file tray also lists the project facts. The right detail pane, toggled by the panel-right button in the header, opens on the selected project with Overview, Citations and Versions tabs; its width and collapsed state are kept in the webview state.

## Build and run

```bash
pnpm --filter @labshelf/vscode build   # host → out/extension.js and out/web/extension.js, reader → dist/reader/, list → dist/library/
pnpm dev:vscode                        # watches the host and the webview bundles
```

- esbuild bundles the extension host from source, including `@labshelf/*`. Other dependencies (pdf.js, Tesseract, the native canvas) stay external and load from `node_modules`, because they locate their data files and binaries next to themselves. `tsc` only typechecks.

- The build also bundles the web extension host (`src/extensionWeb.ts` → `out/web/extension.js`, the `browser` entry of `package.json`). It runs in a browser worker, so esbuild bundles every dependency and a plugin (`build/noNodePlugin.mjs`) fails the build on any import of `node:*`, a Node builtin or a `node/` folder. The browser extension's editor page bundles this file ([browser.md](browser.md#project-editor-page)), and the page answers the web build's host commands ([contract](../contracts/editor-host.md)).
- `pnpm --filter @labshelf/vscode smoke:web` loads the built web extension in VS Code for the web (`@vscode/test-web`, headless Playwright Chromium) and fails unless it activates cleanly. Run `build` first.

- Open the repository in VS Code and press F5. This launches an Extension Development Host. On first run, use **LabShelf: Configure Library**.
- The default local library folder is `~/LabShelf`. When no library is configured, and in **Configure Library**, a pick offers `<sync folder>/LabShelf` for each detected sync folder (Dropbox, Google Drive, OneDrive, iCloud Drive, Nextcloud, Syncthing), `~/LabShelf` (only on this computer), **Choose a folder…** and **How to sync between computers…**. A folder that already holds a library asks "Found your library with N papers. Open it?". When the library is local-only and a sync folder appears, a notification offers to move it; "Not now" stops asking for that tool.
- **LabShelf: Move Library…** moves the library with progress: on the same disk it renames, otherwise it copies, verifies every file and deletes the source. It refuses a target inside the library or a folder that holds files. The device-local cache and state follow the move.
- **LabShelf: How to Sync Between Computers** opens the guide panel.
- **LabShelf: Connect the Browser** installs the browser bridge (a Native Messaging host) for every installed Chrome, Chromium, Brave and Firefox, then lists the browsers it set up and any it could not ([contract](../contracts/bridge.md#host)).
- **LabShelf: Resolve Conflicting Copies**, also offered by the notification "N files have conflicting copies", asks per copy **Keep mine**, **Keep the other** or **Keep both**; `metadata.yaml` has no Keep both ([contract](../contracts/sync.md)).
- The paper list is an in-memory library store rebuilt from the library files on activation. The device-local `index.sqlite` ([contract](../contracts/library-format.md#device-local-files)) holds the embeddings and the content hash of each indexed PDF; deleting it drops them and papers re-index on rebuild.

## Writing projects

- The **Projects** section of the sidebar lists the projects of the library and the external folders added on this device ([contract](../contracts/library-format.md)); its right-click menu holds the project commands, and its header buttons run Browse Templates, New Blank Project and Add Existing Folder. **Browse Templates** opens the template gallery, **New Blank Project** creates an empty project in the library; **Add Existing Folder as Project** registers any folder; **Remove Project from LabShelf** never deletes files.
- The **template gallery** (`labshelf.templates.open`) is an editor tab that lists templates from the LabShelf Community catalog, Typst Universe and My templates, filtered by source, format, category and search, with a detail page per template. **Use template** asks for the project title and creates the project in the library through staging, then opens it. A template whose engine is not installed shows a warning on its detail page. **Save Project as Template** (`labshelf.templates.saveProject`, project context menu) asks for name, category, license, description and authors and stores the project under My templates. **Publish Project as Template** (`labshelf.templates.publish`, project context menu) signs in with GitHub, runs the publish checks and opens a pull request on the Community catalog ([contract](../contracts/templates.md#publish)); a LaTeX project without an engine in `labshelf.yaml` uses the engine the build resolves ([contract](../contracts/templates.md)).
- The extension activates on a folder with `labshelf.yaml`, on LaTeX and Typst files, and on startup, so `labshelf:` links work in any workspace. A link such as `labshelf:vaswani2017#p5` in any file (a code comment, a README) opens the reader at that page on Ctrl+click and shows the paper on hover; a key that matches no paper gets no link, and its hover says so. `vscode://<extension id>/open?link=<percent-encoded link>` opens the same link from outside VS Code ([contract](../contracts/links.md)).
- In a project's sources, citation keys complete from the library, open it in the reader on Ctrl+click. The hover is one compact block: title, byline, two lines of abstract, up to three highlights with their page, the other sections that cite the key, and an **Open paper** link; a key that matches no paper gets no hover. `labshelf.bib` is regenerated from the keys the sources cite ([contract](../contracts/library-format.md#labshelfbib)).
- `.bib` files get diagnostics when they open and when they are saved, never while typing, because the preprint check asks arXiv and CrossRef. A repeated entry (same key, DOI or title) is a warning; an article or proceedings paper without a DOI is a hint; a preprint entry (arXiv, bioRxiv, medRxiv) whose published version is recorded gets a warning, only when that relation exists and never from a title guess. Quick fixes: **Replace with the published version** (keeps the key and the entry's own fields), **Remove the second key** for a repeated key, and **Look up the DOI**, which asks CrossRef only when picked. The generated `labshelf.bib` is skipped.
- Typing `\cite[` (Typst: `@key[`) lists the highlights of the cited paper, or of every paper when the citation has no key yet. Picking one inserts its page (`\cite[p.~4]{key}`, Typst `@key[p. 4]`); a second entry per highlight also inserts the quotation before the citation. The completion opens on the `[` character.
- A paper cited by a project lists, in the detail pane's **Cited in** section, each project, file and heading that cites it; a click opens the source at that line. The section is built from the sources of every ready project, and only VS Code fills it ([contract](../contracts/library-ui-host.md)).
- A project's reading list is the papers its sources cite plus those added by hand (`papers:` in `labshelf.yaml`, [contract](../contracts/library-format.md#labshelfyaml)). **Add Paper to Reading List…** (project context menu) picks from the library. Papers opened while the project is active are not added.
- **Install Project Papers** (project context menu, command palette) imports, one by one with a notification, each paper `papers:` lists that the library has under no paper with that cite key, by its DOI through the core network import with the user's own access, under the listed key. A paper already in the library under another key is reported, never renamed; a taken key gets a letter suffix and the summary says so.
- The **Settings** gear in the sidebar title opens a menu: change the library folder, open the VS Code settings and the AI settings.
- The Library section is the folder tree the browser library page also mounts (`mountLibrarySidebar` from core). Its right-click menu offers the folder commands. A folder row dragged onto another folder moves it. PDFs dragged in from the OS import into the folder under the pointer, and the drag needs Shift held, because VS Code only delivers a drop onto a webview with Shift down.
- **Show Citation Map** (button in the Library view's title bar) replaces the paper list with the works that at least three of the library's papers cite and the library lacks, with a graph of the papers and those works. Import on a row adds the paper by its DOI. The data comes from OpenAlex and is cached in the device-local `openalex/` folder ([contract](../contracts/library-ui-host.md#citation-map)).
- **Research: Open Project** (project context menu) opens the project's main file and its preview beside it, and the Files view's title bar then offers **Close Project**, which closes the project's source tabs and its preview. The open project is remembered per workspace across reloads. While a project is open, focusing one of its files switches the preview to the PDF of the file's build root and builds that root only when it has no PDF yet.
- The open project's title row at the top of Projects opens the project menu on click, Enter or Space, below the row, as Overleaf's project-name menu does. It holds **Publish as Template…** (publishes the project to the template gallery); **Download PDF** (saves the main document's built PDF), **Open PDF in System Viewer**, **Download Source (.zip)** (the project's files without build output and the generated bibliography) and **Download for arXiv (.zip)** (each `.bib` cut to the cited entries); **Export as Word (.docx)**, **Export as Markdown (.md)** and **Export as HTML (.html)**, which convert the main document with pandoc and say so when pandoc is not on PATH; **Make a Copy…**, which installs a copy under a new title in the library's projects folder with the original `labshelf.yaml` under the copy's id, then opens it; the project row's commands with Show Project History; and Close Project. Saves start at `<project id>.<extension>` in the project folder, and an export without a built PDF asks for a build first. Renaming a project is not offered: the `labshelf.yaml` `id` is the project's identity.
- The main document is chosen with **Set as Main Document** (explorer context menu on `.tex` and `.typ` files) or from the status bar item. The item appears on the left while the active editor's file belongs to a project, shows the main file, and opens a quick pick on click.
- **Research: Build Project** compiles the active project (LaTeX or Typst), and every save of one of its sources builds it too. A newer request cancels the running compile and queues one fresh build. Errors, warnings and bad boxes appear in the Problems panel in plain language, located in the source file and line, and the next build of the project replaces them.
- **Research: Show Preview** opens the project's built PDF in the LabShelf reader, building it first when it does not exist; **Research: Build Project** opens the preview beside the editor too. Every later build reloads the preview in place. The preview has a header above the PDF and a footer below it. The header's left group has **Recompile** for the shown root: it shows a dot when the source changed after the last build and spins while a build runs. Its right group is the View group: Compare and Mark (Compare Versions and Mark Version), Dark PDF (pressed while the PDF is dark, and it starts in the theme the preview opens with), Find, the sidebar, then the page field and zoom. The footer shows the shown file and, after it, the section and subsection the visible page belongs to (a click lists the sections to jump to), and on the right the build status: compiling, the shown root's failure with its error count, the source changed since the build, or how long ago it compiled. Clicking a failure opens the build logs of the root it reports. A double-click on the PDF opens the source line behind the point through SyncTeX. The **logs view** lists a root's problems by severity, opens a problem in the source and the raw LaTeX log, and Back to PDF (or Escape) returns to the last PDF that built. **Research: Show in Preview** (`Ctrl+Alt+J`, `Cmd+Alt+J` on macOS, also in the editor's context menu) scrolls the preview to the line under the cursor and marks it. In the preview, hovering a citation (a link, or the text of one) shows a card with the byline and year, the REF or BIB tag, the title, the venue and folder, the citing source line, and the paper's highlights, and clicking it opens the paper in the reader instead of jumping to the bibliography ([contract](../contracts/reader-host.md#preview)). A preview does not save annotations, and its reading position lasts as long as its panel ([contract](../contracts/reader-host.md#preview)).
- The preview's build controls ([contract](../contracts/reader-host.md#preview)): Recompile is muted while the PDF is current, and a source saved after the last build marks the root stale without dimming the PDF. `Ctrl/Cmd+S` in the preview recompiles. The options menu toggles `labshelf.writing.autoCompile` (on by default), which the save listeners and Typst's live compile both honour, and switches the LaTeX engine for `.tex` roots only, written to `labshelf.yaml`. **`<file> only`** appears only when the shown root uses `\include` and builds that file with `\includeonly`. F8 / Shift+F8 walk undefined citations, undefined references, overfull boxes and preprint entries; Typst places only citation problems on the PDF. A citation card offers **Replace**, **Update to <venue>** and **Add to library**, each editing the source or the library and marking the PDF stale. **`N checks`** runs Check Before Submitting against the `check:` limits (`pages`, `words`, `countUpTo`) the preview writes to `labshelf.yaml`. Export opens a save dialog for the project zip or an arXiv zip whose `.bib` keeps only the cited entries of the user's `.bib`, or opens the PDF in the system viewer.
- LaTeX and Typst files wrap long lines at the editor's width, so the text reflows when the window is resized; a user or workspace `editor.wordWrap` setting for those languages overrides it.
- The extension registers the Typst language for `.typ` files, with the file icon Tinymist uses, so Typst sources get the same editor actions as LaTeX without a Typst extension installed; it adds no syntax highlighting, which comes from a Typst extension such as Tinymist. In LaTeX and Typst files of the open project, the editor title bar has **Show Project History**, **Insert Symbol**, **Insert Table**, **Insert Image**, **Search in Project** and **Cite from Library**; **Bold** (`Cmd+B`) and **Italic** (`Cmd+I`) are in its More Actions menu. `Cmd+F` keeps VS Code's search in the current file. VS Code shows at most seven extension buttons there while Split Editor is visible. The edit and insert actions write the markup of the file's language. Show Project History opens the project's history in an editor tab: every save that changed a file, every marked version and every restore, grouped by day, newest first, with the files each entry changed and their line diff. Older and Newer (or the arrow keys) step through it, and Restore this point writes that entry's files back after a confirmation; the state it replaces is recorded first, so a restore can be undone by restoring again. The page also runs Mark Version and Compare Versions. The history is kept per device in the extension's storage, never in the project folder, so sync does not carry it; files over 10 MB and a PDF next to a source of the same name are not recorded. Recompile (`Cmd+Enter`, `Ctrl+Enter` on Windows and Linux) and Show in Preview stay on their shortcuts and in the command palette. Bold and italic wrap every selection in `\textbf{}` / `\emph{}` or Typst `*` / `_`, unwrap a selection that is already wrapped, and put the cursor inside the markers when nothing is selected. The shortcuts apply only inside a project's sources, so `Cmd+B` elsewhere still toggles the side bar. Insert Symbol lists math symbols by category and inserts the LaTeX command (`\alpha`) or `#sym.alpha`. Insert Table asks for columns x rows and inserts a captioned table whose Tab stops walk the cells. Insert Image picks an image file, copies it into the project's `images/` folder under a free name when it lies outside the project, and inserts a captioned figure whose path is relative to the main file's folder (LaTeX) or the current file's folder (Typst).
- **Cite from Library** asks for a paper, then for no page or one of its highlights, and inserts the citation at every cursor. The quote button on a highlight inserts the quotation too. The generated `labshelf.bib` gets the paper's entry.
- **Project Search** is a panel view (the title bar search button, `Cmd+Shift+F` in project sources; the button seeds it with a one-line selection). It searches the project that owns the active file, never other folders, in "This file" or "Project" scope, with Match Case, Whole Word and Regex toggles. Results group by file, a click opens the match, and Replace works for one match, one file or all; **Replace All** asks for confirmation. Replacements are one undoable edit, and files that were clean are saved.
- Build output goes to `<cache>/labshelf/builds/<project id>/`, so the project folder holds no auxiliary files. The PDF is copied next to the main file only when the build succeeds.
- **Research: Check Before Submitting** (command palette, project context menu) saves, builds the project and checks its PDF and sources for desk-reject causes: the page limit, anonymity, Type 3 fonts, low-resolution images and unresolved references. Findings land in the Problems panel under `labshelf-check`, on the source line when the text traces back to one and otherwise on the PDF, and the next check replaces them. What the check holds the PDF to comes from `check:` in `labshelf.yaml` ([contract](../contracts/library-format.md#labshelfyaml)).
- **Research: Mark Version** (command palette, project context menu) asks for a name (`submitted`, `rebuttal`, `camera-ready` or a free name), builds the project and snapshots its sources and PDF under `.labshelf/versions/` ([contract](../contracts/library-format.md#labshelfversions)). Marking a name that exists asks before replacing it.
- **Research: Compare Versions** (command palette, project context menu) picks a version and what to compare it with: another version or the current build, which it builds first. By default it opens both PDFs in side-by-side readers with the changed regions of each page marked, found by diffing the rendered pages. LaTeX projects on a machine with `latexdiff` can instead build one PDF that marks additions and deletions in the text; it is compiled with the project's toolchain into the build folder under `compare/` and opens in a single reader.
- The **Versions** view lists the open project's marked versions, newest first, with the count in its header; it is hidden while the project has none. A row opens the version's PDF in the reader, or shows "PDF missing" when the file is gone. The row menu has **Compare with current** and **Compare with…**, which picks the other side. The view refreshes when `.labshelf/versions/` changes.
- The compiler item in the status bar and **Research: Choose LaTeX Compiler** pick the engine (`tectonic`, `xelatex`, `pdflatex` or `lualatex`), stored in `labshelf.yaml` ([contract](../contracts/library-format.md#labshelfyaml)). The first build offers an installed TeX Live and otherwise Tectonic. Tectonic 0.17.0 is pinned: after consent it is downloaded, checked against its SHA-256 and installed under the extension's `globalStorage`.
- When LaTeX Workshop is installed, a one-time notice per workspace says it builds on save too and offers to turn that off.
- Typst projects compile in the extension with the WASM compiler and need no install. A preview open beside the editor recompiles while the user types, and a save writes `<main>.pdf` next to the main file. Typst's default fonts (9 MB) are downloaded once, after the first Typst build starts, into `globalStorage`. Packages from Typst Universe are downloaded on demand into the folders the Typst CLI uses, so the extension and the CLI share them. After a successful build `labshelf.yaml` records the Typst version; a project last built with another version gets a warning.
- With a Typst project open and the Tinymist extension missing, a one-time notice per workspace (`labshelf.writing.tinymistOfferShown` in `workspaceState`) offers to install it for completion and errors while typing. When Tinymist is installed, LabShelf pins the project's main file in it.
- LaTeX sources are read across the whole project (the main file and the files it includes). `\ref`, `\eqref` and similar commands complete the project's labels, Ctrl+click goes to the `\label`, and a reference to an undefined label is a warning in the Problems panel. The Outline view of the open project lists the active editor's headings (LaTeX sections, Typst headings), marks the one at the cursor and goes to a heading on click; Typst headings come from LabShelf only when Tinymist is not installed.
- Hovering a formula renders it with MathJax, using the project's `\newcommand` and `\DeclareMathOperator` macros. The status bar shows the word count of the whole project, with the active file's count in its tooltip.
- A project with `figures:` in `labshelf.yaml` lists them in the Figures view of the open project, collapsed, with the count beside the title; the view is hidden when there are none. A row marks a figure that is stale (an input is newer) or missing, its tooltip names the newer inputs and the command, and a click opens the figure. **Research: Regenerate Figure** (inline on a stale row, in the context menu of every row) runs the figure's command in the project folder with progress and live output in an output channel, and a failure offers to show that output. The first run of a command asks for confirmation in a modal; the answer is stored in `workspaceState` for that project and that exact command, so another machine, or a changed command, asks again ([contract](../contracts/library-format.md#labshelfyaml)).
- The Checklist view of the open project lists what is left to do, grouped by kind or by section (the toolbar switches, and the choice and the expanded groups are remembered per project): TODOs and broken references with their `file:line`, stale figures, the page overflow against the project's page limit (counted by the preview reader), the project's reading-list papers and the items added by hand. The view's description shows the open count, and the view is hidden while the checklist is empty. Clicking a TODO or reference opens its line; clicking a paper moves it to its next status, and papers marked Done fold into an "N read" row, newest first. A hand-added item is a checkbox row, stored in `.labshelf/checklist.json` ([contract](../contracts/library-format.md#labshelfchecklistjson)); **Add Checklist Item** in the view title adds one and Delete removes it. **Run Check** runs Check Before Submitting.
- A project with `values:` reads its JSON leaves in the sources. In LaTeX, `\lsvalue{` completes the keys and hovering a key shows the value, file and path; in Typst, `json("…")` paths and the members after them complete and show the same hover, for files listed under `values:`. Before every LaTeX build the extension writes `labshelf-values.tex` next to the main file and adds `\input{labshelf-values}` to the main file, in the editor when the file is open ([contract](../contracts/library-format.md#labshelf-valuestex)).
- Commands and environments complete from a catalog of core and common-package names. Typing `}` after `\begin{name}`, or pressing Enter right after it, inserts the matching `\end{name}`.

## Collaboration and sharing

Everything here is the desktop extension host only: sharing needs WebRTC and a disk mirror, which the web build lacks. Each command also appears in the command palette; the contracts hold the behaviour.

- **Share Project…**, **Join Shared Project…** and **Stop Sharing Project on This Device…** share a writing project live with an invite link and keep a full local copy of it ([contract](../contracts/collaboration.md)). Other members' cursors show in the editor, and **Undo My Edit in Shared File** and **Redo My Edit in Shared File** (the undo and redo keys in a shared file) undo only the user's own edits.
- **Connect Cloudflare…** and **Disconnect Cloudflare** deploy and remove the owner's relay Worker from a Cloudflare API token. **Offer My Relay to This Project** and **Withdraw My Relay from This Project** add and remove it in a shared project's relay list ([contract](../contracts/relay.md)).
- Comment threads on the source (the editor's comment gutter, **Comment**, **Resolve** and **Reopen**) are shared with the project, and a note written in a review PDF becomes a thread on its source line ([contract](../contracts/collaboration.md#comments)).
- **Share Folder as Link…** uploads a library folder, encrypted, as a read-only link that opens on the website's share page. **Manage Shared Links…** lists the links and revokes them. **Import Papers from Share Link…** copies the papers of a link into the library ([contract](../contracts/share-link.md)).

## Adding papers

- **Research: Add Paper by DOI or Link…** takes a DOI, arXiv id, PMID, PMCID or article link. It runs the core network import: metadata from the registries, then the core PDF chain ([architecture.md](../architecture.md)). A paper without a free PDF is saved without one.
- No custom resolver is configured and the registries' contact email is the default, until a setting exists.

## Extension host run

Jest mocks `vscode`, and plain Node passes pdf.js's "am I Node?" check, so both hide bugs that appear only in the extension host. The host is an Electron utility process (`process.type === "utility"`), and pdf.js treats it as a browser. Any change to import, OCR, the text layer or pdf.js usage must run in a real host:

1. Create a dummy extension: a `package.json` with `main` and empty `activationEvents`, plus a runner file that exports `run = async () => {…}`. In the runner, `require("vscode")` is real. Require the bundled `out/extension.js` (build first), or bundle the module under test with esbuild.
2. Launch it directly, outside the sandbox. The `code` CLI wrapper detaches, so call the binary. Use a copy downloaded with `@vscode/test-electron`, never `/Applications/Visual Studio Code.app`: a host started from the installed app closes the user's own windows.

   ```bash
   env -u ELECTRON_RUN_AS_NODE "<test-electron copy>/Contents/MacOS/Code" --no-sandbox \
     --user-data-dir=<SHORT path> --extensions-dir=<scratch> --disable-workspace-trust --skip-welcome \
     --skip-release-notes --disable-telemetry --disable-updates \
     --extensionDevelopmentPath=<dummy> --extensionTestsPath=<runner.js> <workspace>
   ```

   `--extensionTestsPath` puts VS Code in test mode, which refuses authentication dialogs. A check that needs an interactive sign-in launches without it.
3. Keep `--user-data-dir` under about 103 characters, because of the IPC socket path limit. The scratchpad path is too long, so symlink it from a short path and delete the symlink after the run.
4. Write runner files with a quoted heredoc (`<<'EOF'`).
5. Stop a stuck run by its own process only: keep the PID of the binary you launched (`$!`) and `kill <pid>`, or match its unique flag with `pkill -f -- "--user-data-dir=<SHORT path>"`. Never `pkill`/`killall` by app name (`Code`, `Electron`, `Visual Studio Code`): it matches the user's own windows and closes every one of them.
6. The runner cannot see contributed views. A "Bad progress location" log line is harness noise.

A cheaper middle ground reproduces pdf.js's environment but not the host lifecycle. Run the script with `ELECTRON_RUN_AS_NODE=1 ".../Code Helper (Plugin).app/Contents/MacOS/Code Helper (Plugin)"`, after setting `process.type = "utility"`.

To test scans, render a real paper's pages to PNG and rebuild an image-only PDF with pdf-lib.

## Webview harness

Webview UI (the reader and the list panel) can only be verified in a real browser:

1. Stub `vscode` through `Module._load`, and bundle and call the HTML builders (the reader shell renderer, the list panel shell) to get the real HTML.
2. Map `asWebviewUri` to a local static server that serves the repository and `pdfjs-dist`.
3. Inject a `:root{--vscode-*}` block with the Dark or Light Modern values.
4. Inject an `acquireVsCodeApi` stub under the page's CSP nonce. The stub records `postMessage` calls and answers the reader's `ready-for-init` with `init`, or the list's `ready` with `navigate` and `snapshot` ([library-ui-host.md](../contracts/library-ui-host.md)).
5. Drive the page over CDP:
   - Click at element centres with `Input.dispatchMouseEvent`.
   - Use modifiers Alt=1, Ctrl=2, Meta=4, Shift=8. `boot.isMac` follows the host, so chords need Meta.
   - Assert on the DOM and on the recorded messages.
   - Read the screenshots. To crop one, use `sips -c H W --cropOffset Y X`.

The CDP harness has known blind spots:

- **Text-layer alignment.** Aiming the pointer at a span's own bounding box always hits, even when the text layer is misaligned with the rendered ink. Outline `.textLayer span` in a screenshot, and assert that the canvas, `.textLayer` and `.annotationLayer` boxes are identical.
- **A perfectly still pointer.** No real hand is perfectly still. Simulate tremor by moving 1 px every ~40 ms, or timer-reset bugs stay invisible.
- **Pointer resting on content.** Park the idle pointer on a margin with no page content.
