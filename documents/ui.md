# UI and UX

Read when designing or changing an app surface. Product purpose and concepts are in [product.md](product.md). This document does not govern the website.

LabShelf should feel like a research workbench: material stays close at hand, related work is easy to consult and the next action is apparent. Balance useful density with a clean workspace. Fluency in research tools should not require learning LabShelf's internal organization.

## Principles

1. **Make basic work self-explanatory.** Importing a paper, reading, annotating, writing a note and starting a manuscript should have recognizable actions and sensible defaults. If these need lengthy instructions, revisit the interaction. Offer advanced configuration when the task calls for it.
2. **Keep the thread of work.** Moving between a paper, note and manuscript should preserve the place the person left. Retain relevant selection, scroll, search and unsaved work. Updates should not reset the surface or take focus away from an edit.
3. **Bring related material within reach.** Support consulting a source while developing a note or writing a manuscript. Use adjacent panes, previews and links where they reduce switching. Let people resize or dismiss supporting views so the main material has room.
4. **Make density serve the task.** Give the current material and frequent actions priority. Group supporting tools and reveal less frequent controls as needed. Avoid both a wall of equally prominent controls and a sparse interface that makes routine work take extra steps. A library list, a note full of equations and a manuscript editor need different arrangements.
5. **Keep sources and results interpretable.** Make source links recognizable and easy to follow. Keep equations readable and code associated with its output. When a result is stale, fails or has not been checked, communicate that state where the person uses it; visual polish must not imply verification.
6. **Let organization grow with the work.** A paper or project is useful on its own. Offer Spaces when grouping material helps; do not make them a setup requirement. Keep a local edit, removing a reference, deleting material and sharing it distinguishable in the interaction.

## Applying the principles

- Design around a concrete task and the material needed to finish it. Reuse an existing interaction when it fits; change its structure when the task needs something different.
- Show research concepts in labels and actions. Storage formats, host protocols and transport details belong out of the basic flow. Source text, code and technical controls remain accessible when they help the researcher.
- Support direct manipulation and discoverable actions, with keyboard access and shortcuts for frequent work. Shortcuts accelerate a usable interface.
- Resolve destructive consequences before committing an action. Confirm destructive operations; avoid routine prompts that merely interrupt safe work. Preserve edits through navigation and recoverable failures.
- Account for empty, loading, error and unavailable states, long content, narrow widths, keyboard focus and light and dark themes. Use semantic controls and accessible names; status must remain understandable without color alone.
- LabShelf is in active development. Screens with mock data, prototype interactions and unfinished controls are expected ways to explore the intended experience. Keep them available for evaluation and distinguish sample content from the user's saved work. Make an action's current limits clear without requiring its screen or navigation entry to be hidden.
- Every deck format opens in one shell. A header holds the mode tabs, the title with a Talk or Poster badge, Saved or Unsaved changes (HTML decks), the build state (compiled decks), Export and the show button. Under it an insert bar, a left panel, the page on a stage with a zoom bar, a properties column and a status bar. The HTML shell has the modes Visual and Code. A compiled talk has Visual, Split, Code and Grid; a compiled poster has Visual, Split and Code. The mode is kept per file. Split and Grid are not offered for HTML decks.
- The show button says Present for a talk (HTML or compiled), Preview for an HTML poster and Real size for a compiled poster. Export is one button, such as Export PDF, when a deck has one export, and a menu otherwise (HTML decks: PDF, HTML file, Share link). A talk's PDF export asks PDF, Handout, 2, 3, 4 or 6 per page, or Notes pages. A poster's PDF export asks for bleed and crop marks.
- The build state of a compiled deck reads Build, Compiling…, Updated or Build failed. A failed build shows Errors (n) when it has errors; clicking it shows the problems. The last good page stays on the stage while a build runs or has failed.
- Decks are edited directly on the slide. In an HTML deck the slide is in a sandboxed frame that runs no scripts, with boxes and resize handles over its blocks. The left panel has the tabs Slides and Elements (a poster has Structure and Elements); the Slides tab holds the slide strip of cached thumbnails. The insert bar has Undo, Redo, New slide with its layouts, a Size menu of presets and custom sizes and the elements to insert. The stage has a zoom bar with select and hand tools, Guides (compiled decks only), zoom out and in, 25–400% or Fit. The floating bar over a block holds its quick text controls. The properties column has the tabs Style and Arrange. Text inside a block is edited in place, and a selection takes bold, italic, underline, strike-through, a colour or a link.
- Several blocks are handled together. A drag on empty space draws a marquee; Shift-click adds or removes a block. The selection moves and resizes as one. Blocks snap to the layout grid and to the edges and centres of others, with dotted guides and equal-spacing marks; Alt turns snapping off. Arrow keys nudge (Shift for 10 px). Arrange has align and distribute. Mod+G groups and Shift+Mod+G ungroups. Copy and paste with Mod+C and Mod+V. Chart in the insert bar adds a chart to a slide.
- Shell shortcuts, outside text fields and the code editor: Mod+Z undoes; Shift+Mod+Z or Mod+Y redoes; Mod+= and Mod+- zoom; Mod+0 fits; Mod+D duplicates the selected slide or block; Mod+C, Mod+V, Mod+G and Shift+Mod+G as above; V selects, H takes the hand and holding Space pans; PageUp and PageDown change slide; Delete or Backspace deletes; Esc clears the selection; Z zooms to the selection or section.
- A linked block carries an Out of date badge with an Update button, or Source missing, in words, not colour alone. A slide or block whose content overflows carries an Overflow mark in words, on its thumbnail in the Grid and as an outline on the page.
- The Style button of the insert bar opens the Style panel in the properties column, for HTML, LaTeX and Typst decks alike. It shows four candidate styles previewed on the current slide, the tokens of the chosen one (colours, fonts, scale), a contrast list in words, the diff of the style block it would write and Apply. Apply is the only action that writes, and it is one undo step. Compiled decks build the previews on demand and say when a build is needed or no toolchain is found. A Kits section lists the user's Kits with Use, makes a Kit From logo, and offers Save as Kit.
- New Presentation and New Poster open a gallery in the browser and in VS Code. It asks for the kind, the format (HTML or the project's LaTeX or Typst), the title, a template card with a preview in the chosen palette, the size and orientation, and a palette: Default, the Style presets or the user's Kits. Talk templates are Blank and Generic; poster templates are Blank, Generic, Better Poster and Billboard.
- An HTML poster is made of sections. The left panel lists them under Structure; dragging a section shows a drop indicator, and a blue line in the gap between boxes resizes its neighbours. The Poster button of the insert bar and the properties of the poster hold Poster Settings: size presets and custom sizes up to 96 in, a Portrait or Landscape switch that reflows the sections, columns, margins, header height and text size. A LaTeX or Typst poster has a Poster button too, with Poster Settings for orientation and spacing; its blocks drag between columns with a drop bar, and the gaps between columns resize them. The status bar reads, for example, "Poster · A1 landscape · 841 × 594 mm".
- A talk's Grid shows every slide as a thumbnail with its number. Drag a thumbnail or press Alt and an arrow key to reorder. The menu of a thumbnail has Duplicate, Delete and Arrange, which sets a layout and keeps the content. A double-click or Enter opens the slide in Visual. For a LaTeX or Typst deck the properties column shows Content and Style tabs with only the properties the block carries, and its code with Open in code. The floating bar of a selected block has Move up, Move down, Duplicate, Delete and Open in code. A click selects the innermost block under the pointer; choosing a structure item in Split shows it in the code. Slides of included files are listed under their file and open in it. A LaTeX talk's Grid and strip also hold the section dividers the build shipped, as cards with a Section mark and the section's title; a selected divider shows its command's line in the code. Blocks and pages are linked only from the build's page map: a poster block without a box has no outline and cannot be picked, and a PDF without a map shows its pages unlinked.
- The presenter has an audience view, full screen when allowed, and a presenter view with notes, the current and next slide, a clock and a timer. The clock shows the local time as HH:MM. The timer starts on the first advance and can be paused and reset. Next is the next slide, not the next overlay step, and beamer section dividers do not count as slides. Both views follow the same slide. Right, Down, Space and PageDown go forward; Left, Up and PageUp back; Home and End to the ends; B blacks the screen; Esc leaves.
- The poster preview shows the whole poster with Mod+wheel zoom, drag or Space+drag pan, and rulers in mm or in. The user calibrates the ruler once per device against a card; until then it says Not calibrated. A Print check lists text below the small-text threshold, images under the print resolution and items inside the safe margin, and the poster is marked at each one; an entry that has no issues says so. A click on an entry centres the poster on it. A minimap shows the visible part of a large poster, and Zoom to section (Z) fits the selected section.
- A shared deck opens in a viewer: the deck in a sandboxed frame under a bar with Present (talks) and Download HTML.
- The chart editor is a fullscreen dialog (`.ls-dialog-full`) over the note, opened by the Chart entry or by a click or Enter on a chart. A 12-tile picker comes first; each tile has an icon and its name, and the arrow keys move between tiles. A data chart has a left navigation (Structure with Traces; Style with General, Traces, Axes and Legend), trace cards, a live preview and a spreadsheet grid below it. A function chart has the tabs Expressions, Axes, X Axis and Y Axis (3D adds Z Axis), a menu to add an expression, rows with a colour dot, a relation and a text field, Variables with an optional slider, and a preview with Zoom in, Zoom out and View full (3D: a rotatable preview). A footer holds Cancel, Apply and Ok. A missing CSV and a failed image say so in words in the editor.
- Esc in the chart editor acts in order: it first leaves an open field or menu, then asks whether to discard unsaved changes (only when there are some), then closes. Cancel asks the same question once the chart has changed.
- The reader's selection bubble holds the colour buttons, Add to note when the paper has a note, and one quote button (Cite…); there is no Send to…. The quote button, the toolbar's and the one on a highlight in Annotations open a small menu with two items, Copy with citation (in the toolbar, Copy citation) and Cite in a project…; Esc or a click outside closes it. Mod+Shift+C copies with the citation directly. In a build preview and for a paper without a cite key there is no menu and the bubble copies directly.
- Cite in a project… is a popup over the reader titled Cite and the key, with the page when there is one. A Project select and a File select sit above a read-only, highlighted view of the `.tex` or `.typ` source, which loads on demand; files are listed recent, main, then alphabetical, and the last choice stays for the reader's life. A click in the source places the citation, shown at the caret as it will be written. With the quotation is a checkbox that appears only when there is a passage; Only add to the bibliography (named, for example, labshelf.bib) appears only without a passage and when the paper is not in it yet. Copy puts the citation on the clipboard, Cancel closes, and Insert (Mod+Enter) writes it and closes. A file that changed since the popup read it is not overwritten: the popup reloads it and asks for the click again, in words. With no project the popup says so and offers Copy and Cancel.

## Math results and step checks

Computed math in a note reads as part of the sentence (`qmd/dom/`). Classes and `--ls-*` tokens only; every state has a glyph or words in the hover card, never color alone.

- **Result states.** A result sits right after its math, typeset like it. Computing: the result dims and pulses, with "Computing…" in the card. Value: normal text. Out of date: dimmed with a ⚠ glyph in `--ls-warning` after it, and "Out of date" and a Recompute action in the card; when recomputing fails, the card says why. An unwritable result shows in `--ls-error`. A note without a runner shows stored results with no action.
- **Equation actions.** Solve appears in the card while an ODE's math is hovered or selected.
- **Step marks.** After an inline math, one small glyph per answered step; in a display math, a gutter at the right with a row per aligned line. ✓ proved is full strength; ≈ sampled is lighter and smaller so it never reads as proved; ✗ differs is `--ls-error` with a wavy underline on the math; ⚠ conditional is `--ls-warning`; ? unread and failed use `--ls-desc`. Marks are hidden while the math is being edited.
- **One shared hover card.** Results, Solve and every mark open the same small card on hover or focus: the state in words, Read as (the Mathematica reading), the rewrites applied, messages, the condition of ⚠ and, for ✗, the counterexample with both sides' values. It closes on leaving, moving focus out or Escape, and its buttons are reachable by Tab right after the anchor.

## Notebook flow

A note's cells, sections and runs share one set of controls in every host (`qmd/dom/`). Classes and `--ls-*` tokens only; each state has a glyph and words, never color alone.

- **Note bar.** A Run all button (its title shows the shortcut), the Advanced switch (a pressed button with a glyph and the word) and a ⋯ note menu: Run all, Restart and run all, Collapse all, Expand all, Next problem, Previous problem, Outline (checked). With Advanced on the bar is a header: Insert, Restart and run all, Collapse all, Expand all, Previous problem, Next problem and Outline (pressed while open) show as buttons with icon and label, with a line under the header. In the reader it sits in the notes pane header; in the library pane, Spaces and a project note, above the note's first item editor. The Outline opens as a panel under it.
- **Cell line.** Run time muted next to Run ("0.4 s", "12 s", "2 min 5 s"). A ⋯ cell menu: Run above, Run below, Collapse cell, Duplicate, Change language, Move up, Move down, Delete (confirmed). A heading shows a collapse chevron and Run section on hover or focus.
- **Collapse is not the code fold.** "Collapse" hides a whole cell to one summary line (`<Language> · <kind> · ran <when>`, with Out of date or May be out of date in it) or a section to its next heading. The existing "Show code" / "Hide code" folds only a cell's code. The two names are never swapped. An error is never hidden by a collapse. With Advanced off a written cell without results shows its summary line in place of its code, and the line opens it; with Advanced on no code is folded and Show code / Hide code is left out.
- **Advanced gutter and current block.** With Advanced off the line numbers show while the pointer is over the gutter. With it on they always show, a thin bar beside each number spans its block (a cell with its outputs is one block) and the caret's bar is stronger; the block holding the caret, a cell's code included, gets a subtle ground while the editor has the focus; it reaches past the block's sides only, never over its neighbours. A text block (paragraph, heading, list, table or a Quarto block kept raw) that takes the caret shows its source, Markdown with its LaTeX and Quarto syntax, in a plain editor in its place, with the caret where it was clicked; arrows past its first or last line, a click elsewhere and Escape show it rendered again, Escape selecting it.
- **Queue.** In a multi-run a waiting cell says Queued and a cell skipped after an error says "Not run: stopped at an error above"; the run status row says "Running k of n" with one Stop.
- **Staleness wording.** A cell's own changed code keeps "Out of date: the code changed". A later cell shows "May be out of date: a cell above changed since this ran" with Run below. The wording says "may" because only order and time are known; no text says checked, current or up to date.
- **Warnings.** One quiet line under the result that opens to the list; never the error style.
- **Keys.** Mod-Enter runs the cell and stays, Shift-Enter runs it and moves past its outputs, Mod-Shift-Enter runs all, F8 / Shift-F8 go to the next / previous problem, Alt-up / Alt-down move the selected cell (Escape selects it from inside the code) or, in a heading, its section, in one undo step. Run buttons show their shortcut in the title.
- **Insert.** A plus appears between blocks on hover or keyboard focus, and on an empty note: Cell (<language>), Equation, Drawing, Chart (Mod-Alt-g), Text, then one Cell entry per other language. The language is that of the nearest cell above.
- **Long output.** Over 30 lines or 3000 characters shows the first 30 lines and "Show all (N lines)"; expanding is not remembered. Headings are sticky inside each editor.

## Implementation

- Reuse shared components in `packages/core/src/ui/dom/` and domain UI such as `libraryUi/dom/`, `reader/dom/` and `qmd/dom/`. Shared surfaces belong in core; hosts supply platform integration.
- Use the token data in `packages/core/src/ui/tokens/`. Generate CSS with `pnpm --filter @labshelf/core tokens`; do not edit generated `tokens.css`. Add a missing design value to the token data instead of hard-coding it in app CSS.
- Use the shared icon set in `packages/core/src/ui/icons/`. Terminal surfaces express the same meanings through text and ANSI color roles.
- `mountOverlay` owns Escape and Tab for the topmost open overlay only; an overlay opened over another (a dialog over a fullscreen editor) answers them, and the one beneath waits. A fullscreen editor adds `.ls-dialog-full` to its content and passes `fullscreen` (a scrim click does not dismiss it) and `onEscape` (returns true when the content used the key, such as closing its own picker).
- Explain a proposed design through the task, arrangement, components and interaction states. Validate the changed flow visually in light and dark and at relevant widths; lint cannot establish that it is understandable or pleasant to use.
