LabShelf: a local-first reference manager for reading and writing

L. Nasser

User manual · labshelf 0.x · October 2026

AbstractThis manual describes LabShelf, a reference manager that keeps your library as a folder of plain files and works inside VS Code, a terminal and the browser. We show how to add papers, read with highlights that carry a meaning, and write LaTeX or Typst with citations checked against what you have read. Select any passage to highlight it, as you would in the reader.

1Getting started

LabShelf has three surfaces that share one library folder: the VS Code extension, the command line and a browser plugin. Figure 6 shows how they talk. Nothing passes through a LabShelf server; the surfaces meet on your disk and on a local port.

1.1Install

In VS Code, search for LabShelf in the Extensions view, or run the first line of Listing 1. The CLI needs Node 18 or later.

Listing 1. Installing the extension and the CLI.
code --install-extension labshelf.labshelf
npm install -g @labshelf/cli
labshelf --version

The browser plugin is on the Firefox and Chrome stores. Pair it from Settings › Import & metadata › Browser plugin.

1.2Choose a library folder

Changed later with labshelf.library.path, see §7.

LabShelf asks for a folder on first run; the default is ~/Research/library. An existing folder of PDFs works: each PDF becomes a paper folder (§2.1).

1.3Add a paper

Drop a PDF on the library, paste a DOI or arXiv link into Add, or use the CLI. Metadata comes from Crossref, arXiv, Semantic Scholar and OpenAlex, asked in that order.

Listing 2. Three ways to add from the terminal.
labshelf add 1706.03762            # arXiv ID
labshelf add 10.48550/arXiv.2010.11929
labshelf add ~/Downloads/paper.pdf  # reads the DOI from the PDF

1.4Coming from another manager

Export your library as BibTeX with file paths and run labshelf import library.bib --pdfs ./attachments. Keys are kept, so documents that cite them keep compiling.

2The library

2.1A paper is a folder

Each paper is a folder named by its cite key, inside the topic folder you choose. It holds the PDF, your notes and a metadata.yaml that LabShelf keeps for you (Listing 3).

Listing 3. metadata.yaml for one paper.
key: vaswani2017
title: Attention is all you need
venue: NeurIPS 2017
status: done
tags: [architecture, nlp]

Move or rename folders in Finder and LabShelf follows. In the side bar, the REF mark tells a paper from a topic folder.

2.2Status and tags

Every paper is Unread, Reading or Done; change it from the list or with Alt 1 2 3. Tags are written #like-this.

2.3Filters

The same filters work in the search box and in labshelf ls (Table 1).

Table 1. Search filters.

FilterFinds
tag:vitPapers tagged #vit
in:VisionPapers in Vision and its subfolders
year:2020..2022Published in that range
status:unreadNot opened yet
--cited-by thesis.texCited by that document

3Reading

3.1Highlights that mean something

Each highlight colour has a meaning you choose. Meanings travel with the highlight: they become headings when you export annotations, and they label your highlights in citation cards (§4.2). The defaults are in Table 2.

Table 2. Default highlight meanings.

ColourMeaningUse it for
yellowKey claimWhat the paper argues
greenMethodHow they did it
blueDefinitionTerms you will reuse
redDoubtWhat you would push back on

3.2Cite a passage with its page

Select text in the reader and choose Cite p.~4. LabShelf copies the citation with the page, in your cite command: \citep[p.~4]{vaswani2017}. When your PDF cites page 4 later, its citation card shows what you highlighted there.

3.3Notes

Notes are a notes.md beside the PDF. Insert highlights pastes your highlights with their pages, grouped by meaning.

4Writing

4.1The preview

LabShelf adds a PDF preview beside your .tex or .typ. The header acts and the footer reads; Figure 9 labels each part.

Recompile turns from muted to full colour when the source has changed. Double-click the PDF to open the source line. Engines: pdfLaTeX, XeLaTeX, LuaLaTeX and Typst.

4.2Citation checks

Every citation in the compiled PDF is checked against your .bib and your library. Table 3 lists what LabShelf finds and how each is fixed.

Table 3. Citation problems and their fixes.

ProblemIn the PDFFix in the card
undefined key(?), red wavy underlineReplace with the closest key on your shelf
published preprintamber wavy underlineUpdate the entry to the published venue
not on your shelfamber wavy underlineAdd to library, with its PDF
broken \ref??, red wavy underlineGo to source
F8 / Shift F8 walk every problem in order.

F8 jumps to the next problem in the PDF, Shift F8 to the previous; overfull lines are included.

4.3Page and word limits

Set a page limit and a word limit from the footer, and choose whether counting stops at the References. Counts include every \include and \input and are saved per root file. Word counts in LaTeX are approximate: macros and math are counted as the PDF shows them.

4.4Build one chapter

In projects that use \include, intro.tex only builds the open file with \includeonly, keeping page numbers and references from the other chapters.

4.5Export

A project .zip, or an arXiv bundle whose .bib holds only what you cite: labshelf export main.tex --arxiv.

4.6A .bib that stays in step

Set labshelf.latex.bibFile in the workspace: new citations are added, removed ones dropped, existing keys never change.

5Projects

A project is a folder with a main .tex or .typ. Opening one shows its files, outline and a checklist (Table 4, Figure 10).

Table 4. Checklist groups.

GroupLists
ReferencesBroken \ref and \cite, with file and line
TODOs% TODO comments and \todo{} notes
FiguresFigures older than the script that makes them
ReadingPapers you cite but have not read
PagesProgress against the limit from §4.3

Mark Version names the current state (“sent to advisor”); Compare Versions shows what changed since; Check Before Submitting runs every check.

6Command line

The CLI reads and writes the same library. Every command takes --json.

Table 5. Commands.

CommandDoes
labshelf add <id|pdf>Add from a DOI, arXiv ID, URL or PDF
labshelf ls [filters]List papers, filters from §2.3
labshelf cite <key>Print a citation; --format bibtex|apa|key
labshelf status <key> doneSet Unread, Reading or Done
labshelf bib sync main.texBring the .bib in step with the citations
labshelf check main.texRun the checks from §4.2; non-zero exit on errors
labshelf export main.tex --arxivWrite the arXiv bundle
Listing 4. Failing a pull request on an undefined citation.
# .github/workflows/paper.yml
- run: npx @labshelf/cli check main.tex

8Privacy

  • No account and no LabShelf server. Your library stays on your disk unless you sync the folder yourself.
  • Metadata lookups send only the identifier.
  • The assistant is off by default; with a local model nothing leaves your computer.
